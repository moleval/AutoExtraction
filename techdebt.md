## Закрыто (история)

### Шаг 4 стабилизации: «двойное создание INSERT» при -BLOCK — ЗАКРЫТ (2026-09-21)
- **История:** первоначально отложен — на версии AutoCAD пользователя после `-BLOCK` в логах «ссылок: 0» (опции Convert/Delete у текстового -BLOCK нет), наивная замена аргумента `""` на `"Delete"` давала бы ошибку (и дала регрессию при первой попытке).
- **Реализация (версионно-устойчивая, без опоры на «Delete»):** подсчёт INSERT имени блока ДО и ПОСЛЕ `-BLOCK`; если команда сама создала вхождение (версии с подсказкой «Преобразовать/Удалить») — повторная вставка не выполняется; если нет — пережившие `-BLOCK` оригиналы (`entget` → живые) стираются через `entdel`, затем ровно один `InsertBlock`/`n1-block-insert`. Печатается контроль «ссылок до/после». Точки: `cs-wrap-to-block` (cutsheet.lsp), упаковка раскладки в `cutline-main` (cutline.lsp).
- **Проверка:** харнесс `/tmp/harness/run_step4_tests.py` — три режима поведения -BLOCK (convert/retain/delete) все зелёные; коммит в ветке arena.
- **Дополнение (по критической оценке):** приём требует РОВНО один новый INSERT (`= oldRefs+1`; прирост >1 — аномалия, повторная вставка отменяется с предупреждением); результат `vla-InsertBlock` проверяется через `vl-catch-all`; финальная печать с вердиктом «(OK: ровно 1 новый)».

### Упаковка раскладки CUTLINE в блок захватывала посторонние объекты — ЗАКРЫТ (2026-10-07, ред. 15-16)
- **Симптом (наблюдение пользователя):** созданный блок раскроя содержит «рандомное количество раскраиваемых элементов»; удаление блока удаляет и их. В живом прогоне в блок попал блок «Ригель (горизонтальный профиль)» с атрибутами.
- **Две причины (обе устранены):**
  1. `-BLOCK` **добавляет к переданному набору предвыделение чертежа** (объекты с grip) — в прогоне это была выборка деталей (7 мультилиний). Мера: `n1-clear-pickfirst` (+ `sssetfirst nil nil`) перед `-BLOCK`, `PICKFIRST`=0 на время команды с восстановлением (ред. 15).
  2. Набор для блока собирался **обходом базы** `entnext` от `(entlast)`: обход идёт дальше конца модельного пространства и затягивает посторонние объекты (в прогоне — 3 `ATTRIB`, вместе с которыми `-BLOCK` уносит в блок их вставку-владельца). Мера: набор строится только из объектов, созданных отрисовкой (`n1-mk` → `*n1-created*`), обход базы оставлен диагностикой (ред. 16).
- **Контроль и откат:** сверка состава блока с раскладкой (`n1-block-type-tally`/`n1-tally-equal-p`) и откат группы раскладки собственной undo-меткой (`n1-wrap-mark-begin/end`). `tu-undo-cancel` для этого не годится: он решает по `DBMOD`, а в уже несохранённом чертеже тот не меняется — в прогоне это дало ложное «изменений БД нет» при фактически созданном блоке.
- **Инварианты:** статическая проверка `cutline-wrap-guard` (учёт своих объектов, набор из `*n1-created*`, скан посторонних, метка отката, вся геометрия через `n1-mk`).
- **Дополнение (ред. 17, по живому прогону):** диагностический скан ред. 16 уронил раскрой — `неверный тип аргумента: stringp <Имя объекта: …>` (определение владельца через `handent` получало значение не того типа; код 330 бывает и handle-строкой, и именем объекта). Исправлено: `n1-owner-name` обрабатывает оба случая, скан и все служебные вызовы — под `vl-catch-all-apply`, печать — через `n1-safe-str`, добавлены пошаговые метки `[CUTLINE][STEP]`. Правило: диагностика не роняет рабочую операцию (закреплено в `cutline-wrap-guard`).
- **CUTSHEET (ред. 25, 2026-10-07): тот же дефект, вторая точка входа.** Набор для блока собирался обходом базы `entnext` — в него попадали ATTRIB/SEQEND динамических блоков; `vla-CopyObjects` падал с «Ошибка Automation. Недопустимый объект-владелец» (атрибут нельзя копировать в определение блока отдельно от INSERT-владельца), а при удачном копировании блок «оригиналов» удалял бы объекты пользователя по всему набору. Устранено: `cs-mk` + `*cs-created*` (набор — только объекты карты), фильтр `cs-copyable-p`, контроль состава блока (`cs-block-type-tally` vs `cs-ss-type-tally`), при несовпадении оригиналы не удаляются и INSERT не вставляется, диагностика `[CUTSHEET][SCAN]`/`[CUTSHEET][STEP]` под защитой, инварианты в `static_check` (`cutsheet-wrap-guard`). **Правило для всех модулей: набор для блока — из учёта созданных объектов, обход базы (entnext) не использовать.**
- **Принято живым прогоном (2026-10-07, ред. 17):** `[STEP]`-метки на месте (старт отрисовки / готово / набор 90 / диагностика завершена), скан нашёл 4 посторонних объекта цепочки БД — ATTRIB ×3 (слой «Обозначения») и SEQEND (слой «Витражи») с владельцем `*U196` (анонимное представление раскраиваемого динамического блока) — и не пустил их в блок; итог `В блоке объектов: 90 (раскладка: 90) — TEXT 46, LINE 27, SOLID 13, LWPOLYLINE 4`, расхождений нет. **Источник посторонних объектов подтверждён:** служебные объекты динамических блоков из цепочки БД (атрибуты/SEQEND и вставки), которые прежде затягивал обход `entnext`; теперь набор для `-BLOCK` строится только из `*n1-created*`, а обход оставлен диагностикой.
