# Извлечение атрибутов из блоков AutoCAD (методика)

Как надёжно читать значения атрибутов вставок (INSERT) из AutoLISP:
два пути чтения, правила защиты от ошибок COM, семантика применения
на примере задачи «Марка» (Заполнение). Реализация —
`Extraction/zapolnenie.lsp` ред. 30 (`zapolnenie-get-attr`,
`zapolnenie-mark-line`); отработана на тестовом стенде
`zapolnenie2.lsp` (удалён после интеграции).

## 1. Два пути чтения атрибутов

### 1.1. ActiveX (основной путь AutoExtraction)

```lisp
(setq attrs (vl-catch-all-apply 'vlax-invoke (list obj 'GetAttributes)))
```

- `GetAttributes` возвращает коллекцию ATTRIB-объектов, принадлежащих
  вставке (не путать с ATTDEF — определениями в описании блока).
- У каждого атрибута читаются `TagString` (имя поля) и `TextString`
  (значение).
- **Плюс:** полный корректный текст в том числе у многострочных
  атрибутов; единообразие с остальным ActiveX-кодом проекта.
- **Минус:** требует `(vl-load-com)`; каждый вызов — COM, нужен контроль
  ошибок (см. §2).

Проверка тега — без учёта регистра, с обрезкой пробелов:

```lisp
(= (strcase (vl-string-trim " " tagname)) (strcase tag))
```

Пустое значение — «атрибут отсутствует»: после
`(vl-string-trim " \t" value)` пустая строка трактуется как отсутствие
атрибута (пустой атрибут в блоке — обычное дело).

Референс: `zapolnenie-get-attr` в `Extraction/zapolnenie.lsp` — один проход по
коллекции, все обращения к COM через `vl-catch-all-apply`, проверки типов
результатов, значение читается только после совпадения тега.

### 1.2. DXF (альтернатива, применяется в MarkZ)

Цепочка после вставки: `entnext` от INSERT даёт ATTRIB-примитивы до
`SEQEND`; значение — DXF-код 1 (`entget`).

- **Плюс:** быстро, не требует ActiveX.
- **Минус:** у многострочных атрибутов код 1 может содержать обрезанный
  текст — продолжение лежит в кодах 3 (`MTEXT`-схема продолжений), его
  нужно склеивать самостоятельно. В проекте MarkZ это учтено
  (`mark:find-attr-in-ename`: цепочка кода −2 + fallback `entnext`),
  там же ActiveX-фоллбек через коллекцию `Attributes`
  (`mark:find-attr-obj`).

**Вывод AutoExtraction:** ActiveX-путь проще в обслуживании и надёжнее
на многострочных атрибутах; производительности хватает с запасом
(933 вставки — незаметно). DXF-путь брать только под измеримые задачи
скорости.

## 2. Правила надёжности

1. **Каждый вызов COM — под `vl-catch-all-apply`**: `GetAttributes`,
   `TagString`, `TextString`. Результат проверяется
   `vl-catch-all-error-p` и на тип (`(= (type x) 'STR)`).
2. **Проверка типа до любой строковой операции.** Строковые функции
   (`strcase`, `strlen`, `substr`, `vl-string-*`) падают
   «неверный тип аргумента: stringp N» на числе. Числа из COM-свойств —
   реальность (динамические свойства, VARIANT), поэтому: сначала тип,
   потом операция. При несовпадении — сообщение с типом и значением и
   безопасная подмена.
3. **Сравнение тегов — `strcase` + `vl-string-trim`**: регистр и пробелы
   в тегах не нормированы.
4. **Читать атрибуты один раз.** Значения извлекаются в агрегации и
   хранятся в записи результата; выводы (таблица, XLS, CSV) не обращаются
   к чертежу повторно.
5. **Компаратор сортировки получает внутреннюю структуру записи** —
   сверять индексы `nth` с фактической структурой, а не с возвращаемой.
   Инцидент «stringp 25»: компаратор был написан под возвращаемую запись
   `(Тип H W Кол-во Марка)`, а `vl-sort` передавал внутреннюю
   `(key Тип H W Кол-во Марка)` — сдвиг на одно поле, `strcase` получал
   количество (25 шт.). Все поля компаратора — с проверкой типа: это
   переводит потенциальный сбой прогона в некритичное поведение.

## 3. Семантика применения: колонка «Марка» (Заполнение)

Утверждённые правила (2026-09-23, подтверждены приёмкой 2026-10-04):

- Атрибут **ВИТРАЖ** — флаг (значение не печатается), атрибут
  **МАРКА** — печатается значение. Регистр тегов не учитывается.
- Комбинации:
  - ВИТРАЖ + МАРКА → `Витраж <значение МАРКА>` (например «Витраж ПФ-115»);
  - только ВИТРАЖ → `Витраж`;
  - только МАРКА → значение МАРКА;
  - оба отсутствуют/пустые → пустая ячейка.
- Колонка «Марка» добавляется **только если** хотя бы у одного принятого
  блока выборки заполнен хотя бы один из атрибутов; иначе вывод 1:1 со
  старым форматом.
- Один Тип/размеры + разные Марки → **разные строки**: марка входит в
  ключ группировки и в порядок сортировки (Тип → Марка → Высота →
  Ширина).

Референс: `zapolnenie-mark-line` в `Extraction/zapolnenie.lsp`.

## 4. Что читать ещё (контекст проекта)

- Видимость динамического блока (имя конфигурации) —
  `su-get-visibility` (`common/select-utils.lsp`): поиск свойства по
  подстроке VISIBILITY/ВИДИМОСТЬ в `GetDynamicBlockProperties`,
  развёртка VARIANT, результат — строка или nil.
- Числовые динамические свойства (габариты) —
  `su-value-to-number` + кэш свойств `su-get-block-props` (Р3.3).
- Общие правила работы с COM в проекте: обёртки через
  `vl-catch-all-apply`, проверки типов, никаких «голых»
  `vla-get-*` без защиты.
