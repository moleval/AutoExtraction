# AutoExtraction — Техническое задание (промт)

## Назначение
AutoExtraction — набор программных модулей для AutoCAD (AutoLISP/Visual LISP), предназначенных для автоматизации подсчёта материалов на основе данных чертежа: погонажа, количества, площади и раскроя.

## Основные возможности
- Выбор объектов по слоям, включая использование групповых фильтров AutoCAD (Фасады, Витражи, Фонари).
- Запуск задач через диалоговое окно (диспетчер) или из командной строки.
- Поддержка двух режимов отчёта:
  - **DETAIL** — детальный перечень с группировкой и промежуточными итогами.
  - **SUMMARY** — сводный отчёт с итогами по типам.
- Экспорт результатов:
  - в Excel (`.xls`) — с формулами (если доступен MS Excel);
  - в текстовый файл (`.gal`) — для передачи в системы раскроя;
  - в таблицу AutoCAD.
- Раскрой хлыста (1D) — отдельная утилита.

## Структура задач
1. **Фасонка** — подсчёт погонажа динамических блоков на слоях типа "Железо".
2. **Подсистема** — подсчёт элементов по значению параметра видимости.
3. **Облицовка** (в разработке) — расчёт площадей блоков и полилиний.
4. **Витраж** (в разработке) — длины профилей/площади стеклопакетов.
5. **Стеклопакеты** (в разработке) — площади стеклопакетов.

## Архитектура
Проект построен по модульному принципу:
- `common/` — переиспользуемые библиотеки (слои, Excel, таблицы, утилиты).
- `Extraction/` — модули задач и диспетчер.
- `docs/` — документация.

## Требования к окружению
- AutoCAD 2016 или новее (проверено на 2016).
- Visual LISP (ActiveX) должен быть доступен.
- Кодировка файлов `.lsp`/`.dcl` — Windows-1251 (ANSI).
- Системная переменная LISPSYS = 0.

### Общие принципы
- Использовать ту же архитектуру, что и в задаче «Фасонка».
- Все задачи вызываются через диспетчер `EXTRACTION`.
- Каждая задача реализуется отдельным модулем в папке `Extraction/`.
- Общие функции выносятся в `common/` по мере необходимости, но не преждевременно.
- Каждая задача имеет функцию `*-main` с одинаковой сигнатурой:
  ```lisp
  (task-main layers report-mode export-excel export-txt create-table save-base)

  1. Подсистема
Назначение:
Подсчёт элементов подсистемы (стойки, ригели, кронштейны и т.п.) по наименованию, получаемому из параметра видимости динамических блоков.

Объекты:
Динамические блоки, вхождения на слоях:

Подсистема

Подсистема оцинкованная

Подсистема алюминиевая

Извлекаемые параметры:

Видимость – состояние параметра видимости (ключевое для наименования).

Длина – опционально, если присутствует у блока; тогда блок считается мерным и для него вычисляется погонаж.

Логика агрегации:

Группировка по наименованию (значение видимости).

Для каждой группы: общее количество блоков и суммарная длина (если длины есть).

Если у блока нет длины, он учитывается только в количестве.

Режимы отчёта:

DETAIL – таблица с колонками: №, Наименование, Кол-во, шт., Суммарная длина, м.п. (пусто, если нет длин).

SUMMARY – общий итог по всем группам: всего элементов, общая длина.

Экспорт:
Excel (eu-export-*), CSV fallback, TXT (GAL) – аналогично Фасонке, но структура данных для Подсистемы проще (одна строка на наименование).

Примечание:
Для извлечения видимости добавить в select-utils.lsp функцию su-get-visibility, которая ищет свойство с именем VISIBILITY или ВИДИМОСТЬ.

2. Облицовка
Назначение:
Расчёт площади облицовочных материалов: кассеты, керамогранит, фиброцементные панели и т.п.

Объекты:

Динамические блоки с параметрами Высота и Ширина.

Замкнутые полилинии, обозначающие площадь.

Извлекаемые параметры:

Для блоков: Высота и Ширина ? площадь одного блока = (В ? Ш) / 1 000 000 (м?).

Для полилиний: площадь через vla-get-area, перевод в м?.

Имя слоя (например, Кассеты, Керамогранит) – используется как тип/наименование.

Логика агрегации:

Для блоков: группировка по типу (имя слоя или очищенное имя блока) и, возможно, по размерам; суммирование площадей и количества.

Для полилиний: группировка по типу (слой), суммирование площадей.

Режимы отчёта:

DETAIL – таблица с разбиением на блоки и полилинии, колонки: №, Тип, Количество, Площадь, м?.

SUMMARY – общая площадь по каждому типу или общий итог.

Примечание:
Возможно, потребуется различать блоки и полилинии в отчёте, а также учитывать, что у блоков могут быть разные размеры.

3. Витраж
Назначение:
Подсчёт длины профилей витражной конструкции.

Объекты:
Мультилинии (MLINE) и/или полилинии, представляющие импосты, стойки, ригели.

Извлекаемые параметры:

Габаритная длина (суммарная длина всех сегментов) – для мультилиний через взрыв и суммирование длин (как в cutline.lsp, функция n1-mline-length).

Для полилиний – длина через vlax-curve-getDistAtParam.

Логика агрегации:

Группировка по типу (слой или имя блока).

Суммирование длин.

Режимы отчёта:

DETAIL – перечень элементов с длинами, сгруппированных по типу.

SUMMARY – суммарная длина по всем элементам.

Примечание:
Возможно, в будущем добавится расчёт площади остекления, тогда понадобятся полилинии стеклопакетов.

4. Заполнение (Стеклопакеты)
Назначение:
Расчёт площади стеклопакетов.

Объекты:
Динамические блоки, представляющие стеклопакеты.

Извлекаемые параметры:

Высота в свету и Ширина в свету – динамические свойства.

Имя слоя (например, Стеклопакеты) – для классификации.

Логика агрегации:

Группировка по имени блока или слою.

Площадь одного стеклопакета = (В ? Ш) / 1 000 000 (м?).

Суммирование количества и площади.

Режимы отчёта:

DETAIL – таблица с размерами и площадями.

SUMMARY – общая площадь.

Примечание:
Если у блока нет параметров высоты/ширины, его можно пропустить или учесть как штучный.
