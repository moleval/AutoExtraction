# Протокол приёмки V3 / V5 / V6 (CUTLINE + CUTSHEET)

Живые прогоны на втором компьютере (`D:\AutoExtraction`). Всё делается на
**обычном рабочем чертеже** (где сотни объектов) в одной сессии AutoCAD.
Порядок: V3 → V5 → V6 → финальный RELOAD. Занимает ~10–15 минут.

## 0. Подготовка (один раз)

```
git fetch origin
git switch arena/01a0cef7-autoextraction
git pull
```

В командной строке AutoCAD: `RELOAD` → в логе должно быть:
`CUTLINE.LSP загружен (ред. 12: ...)` и
`CUTSHEET.LSP загружен (ред. 23: ...)`. Открыть чистый текстовый файл для
копирования лога (F2 в AutoCAD — текстовое окно истории).

Если что-то пойдёт не так — скопируйте весь лог и пришлите.

---

## 1. V3 — диалоги не пропускают мусор

**Суть:** в диалогах параметров раскроя заведомо неверные значения должны
отклоняться: появляется окно-предупреждение (alert), диалог **остаётся
открытым** — вы можете исправить значение или нажать «Отмена». Правильные
значения проходят с первого раза.

### 1.1. CUTLINE (диалог «параметров раскроя», поля «хлыст» и «рез»)

Запустите `CUTLINE` на рабочем чертеже, дойдите до диалога с параметрами.
Вводите в полях «Длина хлыста» / «Рез» по одной строке таблицы и нажимайте
OK. После каждого alert нажимайте ОК в предупреждении (диалог остаётся
открытым) и вводите следующее значение.

| № | Поле | Значение | Почему неверно |
|---|------|----------|----------------|
| 1 | Хлыст | `abc` | не число |
| 2 | Хлыст | `-500` | отрицательная |
| 3 | Хлыст | `0` | нулевая (нужно > 0) |
| 4 | Хлыст | `600000` | больше лимита 500000 мм |
| 5 | Хлыст `6000`, Рез `6000` | рез ≥ хлыста | рез должен быть меньше длины |
| 6 | Рез | `-1` | отрицательный рез |
| 7 | Рез | `1500` | больше лимита 100 мм |

**Ожидание на каждый пункт:** alert
`[AutoExtraction][CUTLINE][VALIDATION] Длина хлыста: число > 0 (лимит 500000 мм). Рез: число от 0 до 100 мм и меньше длины хлыста.`
— диалог НЕ закрылся.

**Контроль (позитив):** введите правильную пару — Хлыст `6000`, Рез `5` →
OK → диалог закрылся, обработка пошла (можно прервать ESC или дать
дойти, чертёж тестовый). Повторите запуск для следующего пункта протокола.

**Отдельно:** запустите ещё раз и нажмите **«Отмена»** в диалоге → команда
должна корректно остановиться (без ошибки, чертёж не тронут).

### 1.2. CUTSHEET (диалог параметров листа: Ширина / Высота / Рез)

Запустите `CUTSHEET`, в диалоге вводите в полях «Ширина листа» /
«Высота листа» / «Рез»:

| № | Поле | Значение | Почему неверно |
|---|------|----------|----------------|
| 8 | Ширина | `abc` | не число |
| 9 | Ширина | `-500` | отрицательная |
| 10 | Ширина | `0` | нулевая |
| 11 | Ширина | `600000` | больше лимита |
| 12 | Ширина | `500000` | граница 500000 не допускается (интервал строгий) |
| 13 | Высота | `50` | граница 50 не допускается (строго больше 50) |
| 14 | Высота | `49` | меньше 50 |
| 15 | Рез | `-1` | отрицательный |
| 16 | Рез `1500` при листе `2000×1500` | рез ≥ стороны листа | рез должен быть меньше меньшей стороны |

**Ожидание на каждый пункт:** alert
`[AutoExtraction][CUTSHEET][VALIDATION] Проверьте размеры листа и ширину реза (рез неотрицательный и меньше сторон листа).`
— диалог НЕ закрылся.

**Контроль (позитив):** Ширина `2500`, Высота `1250`, Рез `5` → OK →
диалог закрылся, обработка пошла.

**Отдельно:** «Отмена» → корректная остановка.

*Примечание: пункты 12–13 (строгие границы) — дополнительная проверка
сверх ревью-списка; если alert вдруг не появился и значение прошло —
просто отметьте этот факт, это не авария.*

## 2. V5 — «мягкий лимит» количества деталей

**Суть:** программа защищена от случайного запуска на огромной выборке.
Мы искусственно занизим лимит до 5 — любой рабочий чертёж его превысит —
и проверим, что программа: (а) показывает окно-предупреждение, (б) пишет
`[GUARD]` в командную строку, (в) спрашивает «Продолжить?», (г) Enter =
останавливается, «Да» = работает дальше.

### 2.1. CUTLINE

1. В командной строке: `(setq *n1-max-parts* 5)` ↵
2. Запустите `CUTLINE`, слои Enter (все), в диалоге — правильные параметры
   (хлыст 6000, рез 5), OK.
3. **Ожидание (три сигнала по очереди):**
   - в логе: `[CUTLINE][GUARD] Обнаружено N деталей при лимите 5. Проверьте выборку/слои.` (N — реальное число объектов вашей выборки);
   - окно: `AutoExtraction / CUTLINE — В выборке N объектов при лимите 5 ... Решение - в командной строке.`;
   - вопрос в командной строке: `Продолжить обработку несмотря на лимит? [Да/Нет] <Нет>:`.
4. **Путь «стоп»:** нажмите **Enter** → в логе
   `[CUTLINE][GUARD] Обработка остановлена пользователем.`, команда
   завершена, чертёж не изменился.
5. Запустите `CUTLINE` снова (лимит всё ещё 5) → на вопрос введите
   **Да** ↵ → в логе
   `[CUTLINE][GUARD] Продолжаю обработку по явному подтверждению.` — и
   обработка идёт штатно до конца. ⚠️ На большом чертеже полный прогон
   долгий: либо дождитесь, либо сразу после этого сообщения прервите
   **ESC** (откат безопасен, V13), либо проверьте ветку «Да» на
   небольшом чертеже.
6. Вернуть лимит: `(setq *n1-max-parts* 10000)` ↵

### 2.2. CUTSHEET

1. `(setq *cs-max-parts* 5)` ↵
2. `CUTSHEET` → диалог (2500×1250, рез 5) → OK.
3. Те же три сигнала с префиксом `[CUTSHEET][GUARD]` («В раскрое принято
   N деталей при лимите 5…»).
4. Первый раз — **Enter** → «Обработка остановлена пользователем.»
5. Ещё раз — **Да** → «Продолжаю обработку по явному подтверждению.»
   (⚠️ то же замечание про долгий полный прогон).
6. Вернуть: `(setq *cs-max-parts* 10000)` ↵

*Отличие семантики (так задумано, не дефект): у CUTLINE счётчик — сырая
выборка ДО отбора мусора, у CUTSHEET — валидные детали ПОСЛЕ отбора.
Числа N в двух тестах могут быть разными.*

## 3. V6 — предохранитель алгоритма раскладки

**Суть:** у алгоритма укладки есть бюджет попыток размещения. Занизим до
5 — алгоритм должен остановиться почти сразу, честно сообщить, сколько
деталей успел разместить, остальное отправить в «НЕРАЗМЕЩЕННЫЕ» —
без зависания и падения.

1. В командной строке:
   `(setq *cs-max-placement-attempts* 5)` ↵
   `(setq *n1-max-placement-attempts* 5)` ↵
2. Запустите `CUTLINE` (хлыст 6000, рез 5) → ожидание в логе:
   `[CUTLINE][GUARD] Алгоритм остановлен ограничителем попыток (5). Размещено: X/Y`
   (X размещено из Y). Чертёж: раскладка не дорисована либо отсутствует —
   это нормально; главное — без зависания и без ошибки.
3. Запустите `CUTSHEET` (лист 2500×1250, рез 5) → ожидание:
   `[CUTSHEET][GUARD] Алгоритм остановлен ограничителем попыток (5). Размещено: X/Y`;
   в конце — список «НЕРАЗМЕЩЕННЫЕ» с остальными деталями.
   ⚠️ Прогон **перезапишет выходной XLS** раскроя (файл по умолчанию
   рядом с чертежом) — это ожидаемо, не испугайтесь.
4. Дождитесь штатного завершения обеих команд (запрос точки вставки —
   укажите точку или ESC).

## 4. Финал — вернуть всё штатно

В командной строке: `RELOAD` — он сбрасывает все четыре переменные к
штатным (лимит деталей 10000, бюджет попыток 1000000). Для контроля
можно проверить: `(setq *n1-max-parts*)` ↵ должно напечатать `10000`.
