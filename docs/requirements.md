# Функциональные требования

Документ описывает текущее поведение системы (ветка с PR #4 и PR #5). Детали
отдельных модулей — в спецификациях: [zapolnenie.md](zapolnenie.md),
[marks-in-maps.md](marks-in-maps.md), [fill-allowance.md](fill-allowance.md),
[search-masks.md](search-masks.md), [fast-tables.md](fast-tables.md).

Задачи, которые ещё не реализованы, помечены явно. Если в тексте нет пометки,
функция работает в текущей версии.

## 1. Диспетчер `EXTRACTION` (команды `EXTRACTION`, `ЭКСТРАКЦИЯ`)

Диалог `extraction.dcl`. Состав:

- **Фильтры слоёв** — чекбоксы **Мои**, **Фасады**, **Витражи**, **Окна** (раздел 1.1).
- **Анонимные блоки** — отдельный чекбокс; относится к панели «Блоки» (имена
  вида `A$C…`), в систему фильтров слоёв не входит.
- **Слои** — список слоёв с множественным выбором, поле поиска, кнопки
  «Выбрать все» и «Снять выделение». Подсказка: если слои не выбраны, поиск
  идёт по всем слоям.
- **Блоки** — панель со списком блоков, полем поиска, полем «Новое имя» и
  кнопками **Копия**, **Вставить**, **Имя** (раздел 1.2).
- **Задачи** — радиокнопки: **Фасонка**, **Подсистема**, **Облицовка**,
  **Витраж**, **Заполнение**. Все пять радиокнопок доступны для выбора.
  **Витраж** — заглушка: сообщение «ВИТРАЖ: модуль в разработке», данные не
  извлекаются (раздел 9).
- **Слои подсистемы** — три чекбокса («Подсистема», «Подсистема алюминиевая»,
  «Подсистема оцинкованная»). Группа активна только при выбранной задаче
  «Подсистема».
- **Режим отчёта** — **Подробный** (DETAIL) и **Краткий** (SUMMARY).
- **Вывод** — чекбоксы `.xls`, `.txt` (фактически пишется GAL-файл `.gal`,
  раздел 11.3) и **AutoCAD** (таблица в чертеже).
- **Раскрой хлыста** и **Раскрой листа** — кнопки запуска модулей раскроя
  (разделы 7 и 8).
- **Поиск** — запускает команду `ПОИСКБЛОК` (англ. синоним `SEARCHBLOCK`; окно поиска, режим «Все блоки», `Extraction/searchattvis.lsp`).
  Диспетчер закрывается перед окном поиска и после него не открывается.
- **Настройки**, **?** (справка), **Сохранить**, **Сохранить как...**, **Плагины…**, **Закрыть**.

Поведение выбора слоёв и фильтров:

- Если ни один фильтр и ни один слой не выбраны, задача выполняется по всем слоям чертежа.
- Если фильтры выбраны, список слоёв показывает объединение слоёв выбранных
  групповых фильтров без дубликатов.
- Если ни один слой не выбран, но фильтр активен, задача выполняется по всем слоям фильтра.
- Если фильтр активен, но слоёв по нему нет, задача не запускается (раздел 1.1, диагностика).

Кнопка **Сохранить** запускает задачу с путём по умолчанию
(`<папка чертежа>\<имя чертежа>_<задача>`). Кнопка **Сохранить как...** открывает
диалог выбора файла и запускает задачу с выбранным базовым именем.

### 1.1 Фильтры слоёв (групповые фильтры AutoCAD)

Типичная структура групповых фильтров чертежа:

```text
Все
 |- Стройплэкс
 |   |- Витражи
 |   |- Окна
 |   |- Отключенные
 |   |- Фасад - Облицовка
 |   |- Фасад - Подсистема
 |   `- Фасад - Утепление
```

- Уровни: 0 — «Все» (корень), 1 — «Стройплэкс», 2 — тематические фильтры.
- **Мои** = весь групповой фильтр «Стройплэкс» рекурсивно (прямые слои и вложенные
  группы любого уровня) + фильтр «Отключенные» по точному имени + фильтры по
  маскам `Фасад*`, `Витраж*`, `Фонар*`, `Окн*`.
- **Фасады** = фильтры по маске `Фасад*`; берутся прямые слои найденных фильтров.
- **Витражи** = фильтры по маскам `Витраж*`, `Фонар*`.
- **Окна** = фильтры по маске `Окн*`.
- Сопоставление имён без учёта регистра, пробелы по краям обрезаются. Маска с `*` —
  шаблон, без `*` — точное имя.
- Несколько чекбоксов объединяются по «или», повторяющиеся слои исключаются.
- Ручной выбор слоёв в списке имеет приоритет над фильтрами. При изменении
  чекбоксов сохраняется только тот выбор, который остался видимым.
- Результат фильтра никогда не подменяется всеми слоями чертежа. Диагностика:
  - нет ни одного группового фильтра — в строке состояния «Групповой фильтр
    отсутствует», в командной строке `[EXTRACTION][LAYER-UTILS] Групповой фильтр отсутствует в чертеже.`;
  - фильтры есть, но слоёв по маскам нет — в окне «Нет слоев по фильтру: <фильтры>»,
    в командной строке `[EXTRACTION][LAYER-UTILS] Групповые фильтры по маскам не найдены: <фильтры>.`
- Маски «Мои / Фасады / Витражи / Окна» — встроенные (`common/layer-utils.lsp`,
  переменные `*tu-layer-filter-*`), в `settings.ini` не хранятся.

### 1.2 Панель «Блоки»

- Поиск по именам блоков поддерживает маски `*`, `?`, `#`, `@` (правила — в [search-masks.md](search-masks.md)).
- **Копия** — копирование выбранного блока (`blockrename-copy-handler`).
- **Вставить** — вставка блока в чертёж (`blockrename-insert-handler`).
- **Имя** — переименование блока через ActiveX по полю «Новое имя» (`blockrename-rename`).
- Переименованный блок остаётся в списке до закрытия диспетчера или ручного
  изменения фильтра/поиска.
- Анонимные блоки (`A$C…`) отбираются чекбоксом «Анонимные блоки».
- Список блоков больше не является заглушкой.
- Если при запуске `EXTRACTION` были выбраны вставки блоков, список показывает только их имена
  (для динамических блоков — видимое имя, `EffectiveName`; анонимное имя `*U…` в список не попадает).
  Без выбора (или если выбор без вставок блоков) — все блоки чертежа.
  Переименованный блок остаётся в списке, как и раньше.
- **Неизменяемые исключения выборки.** Даже при маске `*` из входной выборки всегда исключаются:
  слой `Невидимые` (служебная рамка) и блоки карт прошлых запусков `Раскрой листа*` и `Раскрой *`
  (`common/select-utils.lsp`). Эти исключения не выносятся в поля окна «Настройки».

## 2. Окно «Настройки»

Диалог `settings.dcl`, код `settings.lsp`.

- Выбор задачи (`popup_task`).
- Входные списки: слои, блоки, слои полилиний, слои блоков, имена блоков.
- Для задач Фасонка, Подсистема, Витраж и Заполнение — слой таблицы (`output.table.layer`).
- Для CUTLINE и CUTSHEET:
  - шаблон имени блока карты `output.block.template`: `Раскрой {DWG}` для хлыста,
    `Раскрой листа {DWG}` для листа (`{DWG}` — имя чертежа);
  - слой вставки карты `output.insert.layer` — по умолчанию `CURRENT`;
  - слой рамки карты `output.frame.layer` — по умолчанию «Невидимые».
- Поле **«Свойства длины (маски через ;)»** (`edt_block_length`, ключ
  `task.<ЗАДАЧА> / input.block.length`) активно для задач Фасонка, Подсистема и CUTLINE.
  По умолчанию — `ДЛИНА`. Имя динамического свойства блока считается длиной, если совпадает
  с маской целиком (это приоритет) или содержит маску как подстроку; свойства, в имени которых
  есть «ШИРИНА» или «ВЫСОТА», длиной не считаются никогда — ни при каких масках, включая `*`.
  Пустое поле не сохраняется.
- Поле **«Заполнение: припуск на раму, мм»** (`edt_frame_allowance`, ключ
  `task.ZAPOLNENIE / input.frame.allowance`) активно только для задачи «Заполнение».
  Значение по умолчанию — 26 мм. Принимается только целое число не меньше нуля;
  иное значение отклоняется предупреждением `[AutoExtraction][SETTINGS][VALIDATION]`, и настройки не сохраняются.
- Слой таблицы (`output.table.layer`) задаётся у задач Фасонка, Подсистема, Облицовка,
  Витраж, Заполнение; слой вставки карты (`output.insert.layer`) — только у CUTLINE и CUTSHEET.
  Пустое поле означает прежнее безопасное поведение: для слоя пишется `CURRENT`, для слоя
  рамки — «Невидимые», для шаблона имени — `Раскрой {DWG}` / `Раскрой листа {DWG}`.
  Проверка пустоты своя для каждого поля: поле, неактивное для задачи, диалог очищает,
  и оно не должно обнулять поле другой задачи.
- Кнопки: **По умолчанию** (возвращает значения задачи к умолчанию), **Сохранить** (пишет в `settings.ini`), **Отмена**. Файл читают `RELOAD` и каждое открытие `EXTRACTION`.
- Отсутствующий или пустой ключ `settings.ini` заполняется значением по умолчанию (без предупреждения);
  остальные ключи не затрагиваются.
- Список плагинов (секция `[plugins]`) редактируется кнопкой «Плагины…» в окне `EXTRACTION`
  и записывается сразу после «ОК» в окне плагинов; «Отмена» ничего не меняет. Правила — в §14.

## 3. Задача «Фасонка»

Команда `FASONKA` / `Фасонка`. Файл `Extraction/fasonka.lsp`.

- Обрабатывает вхождения динамических блоков (`INSERT`).
- Наименование — из `EffectiveName`, префикс «Железо » удаляется, первая буква остатка становится заглавной.
- Длина — из динамического свойства блока по маскам `input.block.length` (по умолчанию
  «ДЛИНА», регистр не важен): сначала ищется свойство, имя которого совпадает с маской целиком,
  иначе — первое свойство, содержащее маску. «ШИРИНА» и «ВЫСОТА» длиной не считаются.
- Блоки без длины не попадают в отчёт; если таких нет, выводится «Блоки со свойством 'Длина' не найдены».
- Агрегация:
  - **DETAIL** — группировка «имя + длина», количество и погонаж (длина × кол-во / 1000);
  - **SUMMARY** — группировка по имени, суммы количества и погонажа.
- Выводы: таблица AutoCAD (статические значения), XLS (в строках формула
  `=RC[-2]*RC[-1]/1000` — количество × длина / 1000, в подитогах `SUM`), GAL (раздел 11.3).

## 4. Задача «Подсистема»

Команда `SUBSYSTEM` / `ПОДСИСТЕМА`. Файл `Extraction/subsystem.lsp`.

- **Мерные блоки** (длина найдена по маскам `input.block.length`, по умолчанию «ДЛИНА») — погонаж.
- **Штучные блоки** (длины нет) — только количество.
- DETAIL и SUMMARY; выводы: таблица AutoCAD, XLS/CSV, GAL.
- Нумерация строк DETAIL-таблицы сквозная: штучные позиции получают простой номер
  (1, 2, 3…), а мерные группы продолжают счёт — первая группа получает номер N+1, где N —
  число штучных позиций, и дальше «группа.строка» (14.1, 14.2, 15.1…). Номер группы стоит
  и в строке подитога. Пример рабочего чертежа: 13 штучных позиций дают номера 1…13,
  мерные группы — 14.1…14.16, 15.1…15.23, 16.1…16.7 с подитогами 14, 15, 16.
  Прежняя схема начинала мерные с 2.1 при любом числе штучных, и в таблице получался
  скачок «13 → 2.1», читавшийся как ошибка.
- Если штучных позиций в выборке нет, первая мерная группа получает номер 1, и таблица
  начинается с «1.1».
- В XLS-выгрузке (лист «SubsystemDetail») нумерация тоже сквозная, но без групповых
  префиксов: `1, 2, 3, 4, 5…` по всем строкам.
- GAL содержит только мерные позиции. Штучные позиции в GAL не добавляются.
- Слои подсистемы задаются чекбоксами диспетчера (см. раздел 1).

## 5. Задача «Облицовка»

Команды `CLADDING` / `ОБЛИЦОВКА` и `CLBLOCKS`. Файл `Extraction/cladding.lsp`.

- Обрабатывает полилинии (типы К1–К3) и блоки (Б1–Б4).
- DETAIL и SUMMARY; выводы: таблица AutoCAD, XLS (при сбое — CSV).
- `CLBLOCKS` выводит отдельный отчёт «Блоки облицовки» по слоям, введённым в командной строке
  (Enter — все слои), с количеством найденных кассет/панелей.
- GAL для облицовки не формируется.

## 6. Задача «Заполнение»

Команда `ZAPOLNENIE` / `ЗАПОЛНЕНИЕ`. Файл `Extraction/zapolnenie.lsp`.
Полная спецификация — [zapolnenie.md](zapolnenie.md).

- Элементы — проёмы: стеклопакеты, сэндвич-панели, глухие панели, витражное стекло.
- Размеры извлекаются из свойств блока с приоритетом:
  - высота: «ВЫСОТА В СВЕТУ», затем «ВЫСОТА»;
  - ширина: «ШИРИНА В СВЕТУ», затем «ШИРИНА», затем «ДЛИНА»;
  - поиск свойства: точное совпадение, затем подстрока.
- Припуск на раму — настройка `input.frame.allowance` задачи ЗАПОЛНЕНИЕ (по умолчанию 26 мм);
  см. [fill-allowance.md](fill-allowance.md).
- Видимость отсутствует — берётся `EffectiveName`; блок без размеров или с нулевым размером пропускается с отдельным счётчиком.
- Площадь одного элемента — высота × ширина / 1 000 000, м².
- DETAIL сортируется по Типу, затем по Высоте и Ширине; SUMMARY — по типу.
- Выводы: таблица AutoCAD, XLS (при сбое — CSV), GAL (раздел 11.3).

## 7. Раскрой хлыста (`CUTLINE`, кнопка «Раскрой хлыста»)

Файлы `Extraction/cutline.lsp`, `Extraction/cutline_filter.dcl`.

- Диалог «Раскрой хлыстов»:
  - какие детали резать: **линии**, **мультилинии**, **динамические блоки**, **все типы**
    (с выбором типа мультилинии и типа блока);
  - выбранные слои;
  - **Длина хлыста, мм** и **Ширина реза, мм**;
  - экспорт: `.xls`, **Таблица AutoCAD**.
- Алгоритм: убывающая сортировка деталей и первое подходящее размещение (FFD).
- Деталь длиннее хлыста не размещается и выводится отдельным списком.
- Длина детали-блока — по маскам `input.block.length` задачи CUTLINE (по умолчанию «ДЛИНА»).
- Настройки карты (шаблон блока, слой вставки, слой рамки) — в окне «Настройки» (раздел 2).
- Марки деталей — по разделу 8.1.
- Выводы: XLS (при сбое — CSV «Раскрой хлыстов.csv»), таблица AutoCAD, сообщения в командной строке.

## 8. Раскрой листа (`CUTSHEET`, кнопка «Раскрой листа»)

Файлы `Extraction/cutsheet.lsp`, `Extraction/cutsheet_filter.dcl`.

- Диалог «Раскрой листа»:
  - какие детали: **все типы**, **только полилинии**, **динамические блоки** (с выбором типа блока);
  - выбранные слои;
  - **Ширина листа, мм**, **Высота листа, мм**, **Ширина реза, мм**;
  - **Разрешить поворот деталей на 90°**;
  - экспорт: `.xls`, **Карта AutoCAD**.
- Алгоритм размещения — MaxRects на листах заданного размера с учётом реза.
- Деталь, не помещающаяся на лист, выводится в «НЕРАЗМЕЩЕНО» с размером.
- Блоки заполнения режутся по размеру «в свету» плюс припуск на раму
  (`input.frame.allowance`, по умолчанию 26 мм), см. [fill-allowance.md](fill-allowance.md).
- Неразмещённые детали выводятся в командную строку (`НЕРАЗМЕЩЕНО`) и отдельным разделом в XLS/CSV.
- Марки — по разделу 8.1.
- Выводы: XLS (при сбое — CSV «Раскрой листа.csv»), карта AutoCAD, сводка в командной строке.

### 8.1 Марка элемента (общие правила CUTLINE и CUTSHEET)

- Марка — значение атрибута «МАРКА» вставки блока (тег задан переменной `*AE-MARK-ATTR*`;
  регистр и пробелы по краям не учитываются). У полилиний марки нет.
- На карте раскроя марка подписывается в левом нижнем углу детали, если подпись помещается.
  У деталей без марки подписи нет.
- В перечне изделий хлыстового отчёта — строка на каждую марку с точным количеством;
  изделия без марки — отдельной строкой с прочерком «-». Свёртки вида «+N» нет.
- Марка не влияет на раскрой: число листов и хлыстов не меняется, числа отчёта не зависят от марок.
- Ограничение: детали одинаковой длины взаимозаменяемы, поэтому марка может попасть на соседнюю
  деталь той же длины. Устранение требует переписать решатель (вне текущих задач).
- Отчёт XLS/CSV: порядок колонок **Размер → Тип → Марка**. Колонка «Тип» — состояние видимости
  блока, а не имя блока; если состояния нет, в ячейке «-». Колонка «Марка» появляется,
  только если в выборке есть хотя бы одна марка.
- Подробности — [marks-in-maps.md](marks-in-maps.md).

## 9. Задача «Витраж» — не реализована

- Радиокнопка «Витраж» в диспетчере активна, но `vitrazh-main` в `Extraction/extraction.lsp` — заглушка.
- Выполнение выводит «ВИТРАЖ: модуль в разработке» и выбранные слои; отчёт и файлы не создаются.
- Групповой фильтр «Витражи» (раздел 1.1) работает независимо и подаёт слои в другие задачи.
- Постановка и варианты решения — см. [next-tasks.md](next-tasks.md), пункт «Витраж».

## 11. Экспорт

### 11.1 Excel (`.xls`)

- Файл — XML Spreadsheet 2003 (`<Workbook xmlns="urn:schemas-microsoft-com:office:spreadsheet">`),
  записывается текстом. **Microsoft Excel через COM не используется**, и Excel
  на машине не нужен.
- Формулы — только в XLS, по задаче и режиму; записаны в R1C1-форме XML (например, `=RC[-2]*RC[-1]/1000`).
- Стили — единый набор `eu-xml-styles` (`common/excel-utils.lsp`).

### 11.2 CSV (`.csv`) — фолбэк

- Создаётся, только если запись XLS не удалась (например, файл открыт в Excel).
  Сообщение: «Не удалось сохранить XLS. Сохраняю CSV...».
- Содержит те же данные без формул, с тем же базовым именем.
- Разделитель — `;`. Площади пишутся с десятичной запятой (например, `3,15`).
- Неразмещённые детали раскроя выводятся отдельным разделом в CSV.

### 11.3 GAL (`.gal`) — для станка с ЧПУ

Выводится для Фасонки, Подсистемы (мерные позиции) и Заполнения. Файл `common/txt-utils.lsp`.

- Линейные элементы (Фасонка, Подсистема), по одной строке на позицию:
  `Otr=<имя> <номер>/<количество>/<длина>/`.
- Панели (Заполнение) — заголовок `Размер листа=<размер>`, далее строки
  `<номер>_<тип>/<высота>/<ширина>/<количество>/`.
- Для облицовки и раскроя GAL не формируется.

### 11.4 Таблица AutoCAD

- Создаётся в текущем пространстве модели по указанной точке. Esc — таблица не создаётся, файлы сохраняются.
- Строки создаются с точным количеством (см. [fast-tables.md](fast-tables.md)).
- Оформление — единый стандарт `ts-ac-*` (`common/table-utils.lsp`).

## 12. Обработка ошибок

- Ошибка создания таблицы AutoCAD не прерывает экспорт в файлы.
- Отказ от точки вставки (Esc) — таблица не создаётся, файлы экспортируются.
- Сбой ActiveX при чтении марки или свойства не валит задачу — значение считается отсутствующим.
- При прерывании (Esc или ошибка) UNDO-группа закрывается (`tu-undo-cancel`); системные переменные восстанавливаются в обработчиках `*error*` модулей раскроя и задач.
- Лимиты защиты (не предметные, задаются переменными с дефолтами):
  - максимум деталей: `*n1-max-parts*` (CUTLINE) и `*cs-max-parts*` (CUTSHEET), по 10 000;
  - максимум попыток размещения: `*n1-max-placement-attempts*`, `*cs-max-placement-attempts*`, по 1 000 000.
- Сообщения о фильтрах слоёв в командной строке — `[EXTRACTION][LAYER-UTILS] ...`.
  Единый формат сообщений об ошибках `[AutoExtraction][MODULE][KIND]` запланирован в
  [roadmap.md](../roadmap.md) (принцип 5) и применён не везде.

## 13. Производительность и сервис

- Таблицы AutoCAD создаются с точным количеством строк (без удаления лишних).
- Во время генерации отключаются `CMDECHO` и `REGENMODE`, после — восстанавливаются.
- В тяжёлых раскроях (CUTLINE, CUTSHEET) выводится прогресс в строке состояния (`grtext`).
  Прерывание закрывает UNDO-группу (раздел 12).
- Диагностический протокол: переменная `*EXTRACTION-DIAGNOSTIC*` (`common/task-utils.lsp`), по умолчанию `nil`.
  При `T` выводятся строки `[SCAN]`, `[FILTER]`, `[PACK]`, `[DRAW]`, `[BLOCK]` с количествами.
- Модуль `common/perf-utils.lsp` подключён `RELOAD`'ом, но задачами пока не используется.

## 14. Плагины

- Список плагинов хранится в `settings.ini`, секция `[plugins]`: `plugin.count`,
  `plugin.N.name` (имя файла), `plugin.N.path` (абсолютный путь). Путь выбирает
  пользователь в окне плагинов, которое открывается кнопкой «Плагины…» в окне `EXTRACTION`
  (стандартный диалог `getfiled`, фильтр `.lsp`);
  вручную путь не вводится. Имя берётся из выбранного файла.
- Окно «Плагины»: список в порядке загрузки; кнопки «Добавить…», «Изменить путь…»,
  «Удалить»; строка статуса для выбранного плагина: «найден» или «НЕ НАЙДЕН по пути».
  «ОК» сразу записывает список в `settings.ini`; «Отмена» ничего не меняет.
- Одно имя — одна запись: если выбран второй файл с тем же именем, его путь заменяет путь
  существующей записи.
- `RELOAD` грузит плагины после модулей проекта (секция `--- PLUGINS ---`) в порядке
  записей реестра, то есть по порядку добавления.
- Путь задан и файл по нему есть — загружается этот файл. Путь задан, файла нет — в логе
  строка `НЕ НАЙДЕН по пути <путь>`, плагин не загружается, в окне статус «НЕ НАЙДЕН».
  Другой файл RELOAD не подставляет. Путь пустой — файл `Plugins\<имя>` в корне проекта.
- Поиск плагинов по каталогам разработки не используется.
- Программа не знает содержимого плагинов. Скобки и кодировка плагина проверяются по факту
  ошибки: если загрузка файла завершилась ошибкой, выполняется диагностика CHKPARENS
  (баланс скобок и кодировка), её результат выводится в лог. Заранее, до загрузки, RELOAD
  их не проверяет (решение: проверять по факту возникновения ошибки). Перекрытие имён функций:
  если `(defun NAME)` плагина уже определён проектом или другим плагином, в логе выводится
  предупреждение; загрузка продолжается.
- Имя `plugin.N.name` должно совпадать с именем файла по `plugin.N.path`; иначе в логе
  предупреждение. Повтор имени в реестре пропускается с записью в лог.
- Подключён `PlotFrame.lsp` (v1.09) — печать рамок и форматов СПДС в PDF и на принтер; команды перечислены в [START.md](START.md) («Плагины»).
- Кнопка «Плагины…» находится в диспетчере `EXTRACTION` (между «Сохранить как...» и «Закрыть»);
  в окне «Настройки» её нет.
- Замена пути при добавлении файла с именем из реестра выполняется без сообщения.
- Подробности — в [START.md](START.md).

## 15. Поиск (`SEARCHBLOCK` / `ПОИСКБЛОК`, `SEARCHATTR` / `ПОИСКАТР`, `SEARCHVIS` / `ПОИСКВИД`)

- Файлы: `Extraction/searchattvis.lsp` (логика и команды), `Extraction/searchattvis.dcl` (окно).
  Модуль грузится `RELOAD` после `blockrename.lsp`.
- Запуск:
  - кнопка **Поиск** в диспетчере `EXTRACTION` (рамка справа от «Раскрой», рядом с «Настройки» и «?»)
    запускает `ПОИСКБЛОК` (режим «Все блоки»). Диспетчер закрывается перед окном поиска и после него не открывается;
  - `ПОИСКБЛОК` (`SEARCHBLOCK`) — окно, режим «Все блоки»;
  - `ПОИСКАТР` (`SEARCHATTR`) — окно, режим «Блоки с атрибутами»;
  - `ПОИСКВИД` (`SEARCHVIS`) — окно, режим «Видимости блоков». Все три команды открывают одно и то же окно;
    режим переключается радиокнопкой в окне;
- Скорость (большой чертёж, много динамических блоков): списки окна перерисовываются только при изменении строк;
  записи и группы считаются без квадратичного перебора; записи окна считаются один раз на сочетание режима и запросов
  (щелчки по спискам их не пересчитывают); в командной строке печатаются время сбора данных
  при поиске («Поиск: вставок N, сбор данных X мс.») и время расчёта при «Подсчёт» («Подсчёт: расчёт X мс.»).
- Область: предварительное выделение, если оно есть; иначе весь чертёж. Учитываются вставки блоков
  в пространстве модели, в том числе анонимные. Вставки на замороженных, заблокированных и выключенных
  слоях в результат не попадают.
- Окно — рамка **Режим** (радиокнопки «Все блоки», «Блоки с атрибутами», «Видимости блоков»; переключение
  в том же окне) и рамка **Поиск** с тремя полями, подсказки внутри полей:
  - «Блок (по Enter):» — маска имени блока; фильтрует список блоков во всех режимах;
  - «Атрибут (по Enter):» или «Видимость (по Enter):» — в режимах «Блоки с атрибутами» и «Видимости блоков»;
    в режиме «Все блоки» поле отключено;
  - «Значение (по Enter):» — условие по значению. Условие применяется по Enter. Пустое поле не ограничивает выборку.
- Окно — два списка: слева — **Блоки**; справа — **Атрибуты** (режим «Блоки с атрибутами») или **Видимости**
  (режим «Видимости блоков»). В режиме «Все блоки» правый список пуст, его высота и размер окна не меняются.
- Режим «Все блоки»: одна строка на блок, без пунктов. Поле «Значение» сравнивается только с «Длина»
  (динамическое свойство или атрибут с таким именем). Без выбора **Подсчёт** выводит одну таблицу
  с заголовком «Все блоки: N шт.» (N — число вставок по фильтру). Смена режима очищает поля «Атрибут/Видимость»
  и «Значение»; поле «Блок» сохраняется.
- Правила поиска — как у полей «Поиск» в панелях «Слои» и «Блоки» (см. [search-masks.md](search-masks.md)):
  без учёта регистра; запрос без знаков `* ? # @` ищется по вхождению; запрос со знаками работает
  как маска целиком; запятая означает ИЛИ. Выбранные пункты одного списка объединяются по ИЛИ;
  между списками и полями действует И.
- Режим «Блоки с атрибутами»: в правом списке строка «атрибут» или «атрибут | значение». Поле «Атрибут» ищет
  среди имён атрибутов, поле «Значение» — среди их значений.
- Режим «Видимости блоков»: атрибуты не участвуют. Поле «Видимость» ищется среди значений всех параметров
  видимости, поле «Значение» — среди значений остальных динамических свойств. Строка правого списка:
  `состояние` или `состояние | значение (имя свойства)`, например `Видимый | 1500 (Длина)`.
- Перекрёстный отбор: выбор блоков сужает правый список (остаются пункты, которые есть у этих блоков);
  выбор пунктов правого списка сужает левый.
- Строка состояния: при выборе — полный текст выбранных строк (в списках длинные строки обрезаются);
  без выбора — «Блоков: N, вставок: K. Область: …»; в режиме «Блоки с атрибутами» добавляется «атрибутов: M»,
  в режиме «Видимости блоков» — «видимостей: M».
- Кнопки:
  - **Выбрать** — выделяет в чертеже вставки текущей области окна, которые проходят все выбранные условия; если выбраны
    только блоки, берутся все их вставки. Окно закрывается, в командную строку выводится число вставок;
  - **Выбрать подобное** — выделяет во всём пространстве модели чертежа вставки, аналогичные выбранному образцу
    по выбранному блоку, видимости или атрибуту (в списке или соответствующем поле ввода): если поле «Значение»
    не заполнено — по блоку, видимости или атрибуту; если «Значение» введено — аналогичные элементы с подходящими
    значениями. При вводе или очистке «Значения» выбор в правом списке переносится автоматически;
  - **Подсчёт** — открывает окно «Подсчёт» по выбранным блокам (с учётом выбранных пунктов). Окно поиска
    закрывается на время подсчёта и открывается снова с тем же выбором и условиями после кнопки «Закрыть» или Esc
    в окне «Подсчёт»; после успешной «Таблицы AutoCAD» или «Копировать» закрываются окна «Подсчёт» и «Поиск»,
    диспетчер не открывается;
  - **Сбросить выбор** — снимает выбор в обоих списках, окно не закрывается;
  - **Закрыть** и Esc — закрывают окно без действий.
- Окно «Подсчёт» (кнопка **Подсчёт**; DCL держит одно окно, поэтому окно поиска закрывается на время подсчёта):
  - список — таблица с рамкой: линии над шапкой, после шапки, после позиций и после итога; ячейки замкнуты
    символами «|» по вертикали и «-» / «+» по горизонтали (дефисов столько, чтобы линия доходила до следующего «+»);
    справа — закрывающие «|» и «+» на правой границе таблицы; колонки
    площадь: № | Высота | Ширина | Кол-во | Всего (без марок) или № | Марка | Высота | Ширина | Кол-во | Всего (с марками);
    погонаж без площади: № | Длина | Кол-во | Всего (без марок) или № | Марка | Длина | Кол-во | Всего (с марками).
    Если в выборе есть и площадь, и погонаж, — два списка подряд: сверху площадь (свои колонки), снизу погонаж
    (колонка «Длина», без пустых колонок); у каждого своя ширина колонок; диалоги searchattvis_count_xn / _xm.
    Высота и ширина — отдельными колонками, числами в мм (площадь: «2100» и «900»); погонаж — длина в колонке «Длина».
    Кол-во — «2 шт.», всего — «3.78 м2» или «3.00 м.п.». В копии и в «Таблице AutoCAD» колонки те же, что в данных:
    «Высота», «Ширина» (площадь) или «Длина, мм» (погонаж), без «x» внутри ячейки.
    Разделы подряд, между ними пустая строка; у каждого раздела свой итог «Всего:» (количество и сумма), последним в разделе.
    Без выбора блока подсчёт идёт по выбранным видимостям или атрибутам; заголовок таблицы — их названия.
    Если не выбрано ничего — «Выберите блок в списке слева»; у блока нет погонажа или площади — «У блока «…» нет погонажа или площади»,
    далее в той же строке: «Вставок: N, на замороженных, заблокированных или выключенных слоях: K. Свойства: имя=значение; …»
    (первые 8 свойств первой вставки — для поиска причины);
    размер читается из текста с ведущим числом («1500», «1500.0», «1500,5», «1500 мм»);
  - заголовок над каждой таблицей — название выбранного блока по центру таблицы; несколько блоков — каждое в своей строке;
    длинное название переносится по словам;
  - в режиме «Видимость» при выборе двух и более видимостей — отдельная таблица на каждую видимость;
    заголовок её таблицы — название этой видимости; в копии перед каждой таблицей — пустая строка и заголовок;
  - ширина колонок (символов): площадь без марок — № 3, Высота 7, Ширина 7, Кол-во 6, Всего 9; с марками — № 3, Марка 20, Высота 7, Ширина 7, Кол-во 6, Всего 9; погонаж без площади — № 3, Длина 7, Кол-во 6, Всего 9; с марками — № 3, Марка 20, Длина 7, Кол-во 6, Всего 9.
  - строка состояния «Всего: …» выровнена по правому краю окна.
    Пробел слева от первой колонки и справа после последней: таблица не липнет к краям окна.
    Перевод в единицы DCL: 1 символ ≈ 1,2 единицы (замер по скриншоту AutoCAD: один символ ≈ 10,6 px, единица ≈ 9 px).
    Ширина списка (единиц) = 1,2 × (сумма (колонка + «| ») + 2 пробела по краям) + 6; не меньше ширины кнопок (48).
    Итог: площадь без марок — 59, с марками — 85; погонаж без марок — 50, с марками — 74.
    Высота списка 40 строк (при смешанном выборе: список площади 24 строки, список погонажа 16). Окно выбирает вариант по данным: есть ли площадь (колонки «Высота» и «Ширина») и есть ли колонка «Марка».
    Значение длиннее колонки сдвигает строку на экране; тест проверяет типичные примеры, не все возможные значения.
    Строка состояния — итог по выбору («Всего: N шт. S м.п.»), по ширине может не поместиться при смешанном выборе;
  - погонаж — свойство «Длина» без номера (регистр не учитывается); «Длина1», «Длина2» не берутся;
  - площадь — размеры по цепочке ЗАПОЛНЕНИЯ: «Высота в свету» и «Ширина в свету», затем «Высота» и «Ширина»;
    для каждого ключа сначала точное имя (регистр не важен), затем вхождение в имени без цифр:
    «Высота двери» берётся, «Высота1» — нет; если «Ширины» нет, берётся «Длина»;
    если «Высоты» нет, блок в площадь не попадает;
  - припуск на раму: к высоте и ширине блоков, у которых имя или первое значение видимости подходит под
    маски задачи ЗАПОЛНЕНИЕ (`input.block`, как у раскроя), добавляется припуск (`input.frame.allowance`,
    по умолчанию 26 мм); пустой список масок — припуска нет; у остальных блоков припуска нет;
    погонаж припуска не получает. Сначала размер округляется до мм, затем добавляется припуск;
  - размеры округляются до миллиметров до агрегации; группы — по размеру, при наличии атрибута «Марка» — по паре
    «Марка + размер»; сортировка: по марке (естественный порядок, «М2» раньше «М10»),
    затем по высоте и ширине (по возрастанию; для погонажа — по длине);
  - единицы: м.п. (погонаж), м2 (площадь), 2 знака после запятой. Строка «Всего:» — последняя в разделе (количество и сумма
    общие), номера — только у позиций. В таблице AutoCAD колонки погонажа: № | Марка | Длина, мм | Кол-во | Сумма, м.п.;
    площади: № | Марка | Высота | Ширина | Кол-во | Сумма, м2. Без атрибута «Марка» колонка не выводится;
  - строка состояния всегда показывает итоги: «Всего: N шт. S м.п.» или «Всего: N шт. S м2»; если есть оба раздела —
    через «; »; без данных — «Всего: 0 шт.». Выбор строки списка её не меняет;
  - **Копировать** — список в буфер обмена (вставка в Excel; результат выводится в командную строку); **Таблица AutoCAD** — таблица в чертеже по точке: первая строка — название динамического блока (жирным), вторая — шапка колонок, колонки шире, без переносов; «Высота», «Ширина», «Кол-во», «Длина» — по центру, «Сумма» — вправо;
    после каждой из них окна «Подсчёт» и «Поиск» закрываются. **Закрыть** и Esc — возврат в окно поиска с тем же выбором.
- Таблица команд (при ручной загрузке и при `RELOAD`): `SEARCHBLOCK / ПОИСКБЛОК`, `SEARCHATTR / ПОИСКАТР` и `SEARCHVIS / ПОИСКВИД`.
