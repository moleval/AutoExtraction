# Функциональные требования

Актуально на редакцию `ee8fb89` (PR #5). Подробные методики и протоколы приёмки — в связанных документах, ссылки даны в разделах.

## 1. Диспетчер задач

- Открывается командой `EXTRACTION` или `ЭКСТРАКЦИЯ`.
- Окно содержит:
  - Четыре независимых чекбокса фильтров слоёв: **Мои**, **Фасады**, **Витражи**, **Окна** — поиск по именам групповых фильтров AutoCAD (см. 1.1).
  - Чекбокс **Анонимные блоки**: в панели «Блоки» оставляет только анонимные блоки (имена вида `A$C…`). В систему фильтров слоёв не входит.
  - Список слоёв с множественным выбором (сортировка по алфавиту, без дубликатов) и полем «Поиск» (маски `*`, `?`, `#`, `@`, см. [search-masks.md](search-masks.md)).
  - Панель «Блоки»: поле «Поиск» (подтверждается Enter), список блоков и кнопки **Копия**, **Вставить**, **Имя**. Эти кнопки работают с выбранным блоком и не меняют правила отчётов.
  - Радиокнопки задач: **Фасонка**, **Подсистема**, **Облицовка**, **Витраж**, **Заполнение**. Витраж — в разработке: выводит сообщение «модуль в разработке», отчёта нет.
  - Радиокнопки режима отчёта: **Подробный** и **Краткий**.
  - Чекбоксы вывода: `.xls`, `.txt` (в файл `.gal`), `AutoCAD`.
  - Кнопки **Раскрой хлыста** и **Раскрой листа** (см. раздел 6).
  - Кнопки **Настройки** (см. раздел 10), **?** (справка), **Сохранить**, **Сохранить как...**, **Закрыть**.
- При включении любого фильтра слоёв список обновляется, отображая объединение слоёв выбранных групповых фильтров. Дубликаты исключаются.
- Если ни один фильтр не выбран, отображаются все слои.
- Если ни один слой не выбран, но активен фильтр, задача выполняется по всем слоям фильтра.
- Если ни один фильтр не выбран и ни один слой не выбран, задача выполняется по всем слоям.
- Если фильтр активен, но слоёв не дал, задача не запускается (см. раздел 1.1).

## 1.1 Фильтры слоёв (групповые фильтры AutoCAD)

Структура групповых фильтров чертежа:

```text
Все
 |- Стройплэкс
 |   |- Витражи
 |   |- Окна
 |   |- Отключенные
 |   |- Фасад - Облицовка
 |   |- Фасад - Подсистема
 |   `- Фасад - Утепление
```

- Уровни определяются вложенностью: 0 — «Все» (структурный корень), 1 — «Стройплэкс», 2 — тематические фильтры.
- **Мои** = весь групповой фильтр «Стройплэкс» рекурсивно (прямые слои и все вложенные группы любого уровня) + групповой фильтр «Отключенные» явно по точному имени + фильтры по маскам `Фасад*`, `Витраж*`, `Фонар*`, `Окн*`.
- **Фасады** = фильтры по маске `Фасад*` (уровни 1-2); берутся прямые слои найденных фильтров.
- **Витражи** = фильтры по маскам `Витраж*`, `Фонар*`.
- **Окна** = фильтры по маске `Окн*`.
- Сопоставление имён: без учёта регистра, с обрезкой пробелов по краям; маска с `*` — шаблон, без `*` — точное имя.
- Несколько чекбоксов объединяются по «или», повторяющиеся слои исключаются.
- Ручной выбор слоёв в списке имеет приоритет над фильтрами; при изменении чекбоксов сохраняется только тот выбор, который остался видимым.
- Диагностика (результат фильтра никогда не подменяется всеми слоями чертежа):
  - в чертеже нет ни одного группового фильтра — в строке состояния окна «Групповой фильтр отсутствует», в командную строку `[EXTRACTION][LAYER-UTILS] Групповой фильтр отсутствует в чертеже.`;
  - групповые фильтры есть, но слоёв по ним нет — в окне «Нет слоев по фильтру: <фильтры>», в командную строку `[EXTRACTION][LAYER-UTILS] Групповые фильтры по маскам не найдены: <фильтры>.`
- Маски фильтров не входят в `settings.ini`: «Мои/Фасады/Витражи/Окна» — встроенные настройки диспетчера (`common/layer-utils.lsp`, переменные `*tu-layer-filter-*`).
- Кнопка `Сохранить` запускает задачу с путём по умолчанию (`<папка чертежа>\<имя чертежа>_FASONKA`).
- Кнопка `Сохранить как...` открывает диалог выбора файла, затем запускает задачу с выбранным базовым именем.

## 2. Задача «Фасонка»

- Обрабатывает вхождения динамических блоков (`INSERT`).
- Наименование формируется из `EffectiveName`, удаляется префикс «Железо », первая буква остатка становится заглавной.
- Длина извлекается из динамического свойства, имя которого содержит «ДЛИНА» (без учёта регистра).
- Блоки без длины игнорируются.
- Агрегация:
  - **DETAIL**: группировка по «имя + длина», вычисление количества и погонажа (длина x кол-во / 1000).
  - **SUMMARY**: группировка по имени, суммирование количества и погонажа.
- Выводы:
  - Таблица AutoCAD (если включено): статические значения, без формул.
  - Excel (если включено): в строках формулы `=RC[-2]*RC[-1]/1000` (количество x длина / 1000) и `=SUM(...)` в подитогах.
  - GAL (`.gal`, если включено): текстовый файл для станка с ЧПУ, строки формата `Otr=имя номер/количество/длина/`.

## 3. Экспорт в Excel

- `.xls` — это XML Spreadsheet (SpreadsheetML), файл создаётся без Microsoft Excel и без COM.
- Если файл записать не удалось (чаще всего он открыт в Excel), программа сохраняет CSV с тем же базовым именем и теми же данными, без формул.
- CSV: разделитель `;`, для Подсистемы и Заполнения — десятичная запятая.

## 4. Обработка ошибок

- Отсутствие блоков со свойством «Длина» — сообщение «Блоки со свойством Длина не найдены».
- Ошибка при создании таблицы AutoCAD не должна прерывать экспорт в файлы.
- Отказ от точки вставки таблицы (Esc) — таблица не создаётся, но файлы экспортируются.
- Ошибка записи XLS — переход на CSV (раздел 3), сообщение в командной строке.

## 5. Производительность

- Создание таблицы AutoCAD с точным количеством строк (без удаления лишних).
- Отключение `CMDECHO` и `REGENMODE` на время генерации.
- Прогресс и отмена по ESC — в длинных задачах раскроя.

## 6. Раскрой (CUTLINE, CUTSHEET)

- **Раскрой хлыста** (`CUTLINE`, `РАСКРОЙХЛЫСТА`): линейный раскрой деталей из линий, мультилиний и вставок блоков на хлыстах заданной длины с учётом реза. Выбор деталей — по слоям диспетчера; ручной выбор слоёв имеет приоритет над фильтрами.
- **Раскрой листа** (`CUTSHEET`, `РАСКРОЙЛИСТА`): двумерный раскрой деталей (полилинии и вставки блоков) на листах заданного размера с учётом реза; оптимизация последнего листа.
- Результат: карта раскроя вставляется блоком. Имя блока задаётся шаблоном `output.block.template` (`Раскрой {DWG}` / `Раскрой листа {DWG}`), слой вставки — `output.insert.layer`, слой рамки — `output.frame.layer` (по умолчанию «Невидимые»). Настройки — в `settings.ini`, раздел `[task.CUTLINE]` / `[task.CUTSHEET]`.
- Неразмещённые детали выводятся в командную строку (`НЕРАЗМЕЩЕНО`) и отдельным разделом в XLS/CSV.
- Отчёты XLS и CSV, порядок колонок во всей выгрузке листа: **Размер, затем Тип, затем Марка**. Колонка «Тип» — состояние видимости блока (значение параметра «Видимость»), а не имя блока; если состояния нет, в ячейке «-».
- Колонка «Марка» появляется только тогда, когда в выборке есть хотя бы одна марка (раздел 7).
- Числа отчёта (листов, хлыстов, изделий, КПД) не зависят от марок и от подписей на карте.
- Подробности и проверки в живом прогоне — [marks-in-maps.md](marks-in-maps.md), [acceptance-layer-filters.md](acceptance-layer-filters.md).

## 7. Марка элемента

- Марка — значение атрибута «МАРКА» вставки блока (тег задан константой `*AE-MARK-ATTR*`, регистр и пробелы по краям не учитываются). У полилиний марки нет.
- На карте раскроя марка подписывается в левом нижнем углу детали, если подпись помещается; у деталей без марки подписи нет.
- В перечне изделий хлыстового отчёта — строка на каждую марку с точным количеством; изделия без марки — отдельной строкой с прочерком «-». Свёртки вида «+N» нет.
- Марка не влияет на раскрой: решатель не знает о марках, число листов и хлыстов не меняется.
- Ограничение: детали одинаковой длины взаимозаменяемы, поэтому марка может попасть на соседнюю деталь той же длины. Устранение требует переписать решатель (за рамками текущих задач).
- Подробности — [marks-in-maps.md](marks-in-maps.md).

## 8. Блоки заполнения: размер в свету и припуск на раму

- Признак блока заполнения — маски блоков задачи ЗАПОЛНЕНИЕ (`task.ZAPOLNENIE / input.block`) по EffectiveName и «Видимость».
- Размер берётся «в свету» (`ВЫСОТА В СВЕТУ`, `ШИРИНА В СВЕТУ` и варианты без префикса), к нему добавляется припуск на раму — настройка `task.ZAPOLNENIE / input.frame.allowance`, по умолчанию 26 мм.
- Если размер «в свету» не найден, деталь исключается с причиной; подмены габаритом блока нет.
- Тот же припуск применяется в отчёте «Заполнение» и в «Раскрое листа» — размеры совпадают.
- Подробности — [fill-allowance.md](fill-allowance.md).

## 9. Плагины

- Сторонние модули загружаются командой `RELOAD` после модулей проекта (секция `--- PLUGINS ---`).
- Источник: каталоги разработки (`*ae-reload-plugin-dev-dirs*`, приоритет) или папка `Plugins\` проекта.
- Подключён плагин `PlotFrameToPDF.lsp` (печать области рамкой в PDF).
- Порядок настройки и особенности — [START.md](START.md), раздел «Плагины».

## 10. Окно «Настройки» и settings.ini

- Кнопка **Настройки** открывает окно правил задач. Поля: тип задачи, слои и блоки (маски через `;`), для Облицовки — слои полилиний, слои блоков и имена блоков, для Заполнения — припуск на раму (целое >= 0), слой таблицы (`CURRENT` — текущий), имя выходного блока карты (`{DWG}` — имя чертежа), слой вставки карты, слой рамки карты.
- Кнопка **По умолчанию** возвращает значения задачи к умолчанию; **Сохранить** пишет их в `settings.ini`. Файл читают `RELOAD` и каждое открытие `EXTRACTION`.
- Некорректные значения (имя выходного блока с запрещёнными символами, припуск не целое число или отрицательный) отклоняются с предупреждением, значения не сохраняются.
