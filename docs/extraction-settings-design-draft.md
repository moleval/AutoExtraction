# Проектирование настроек EXTRACTION — согласованный черновик

Статус: **логика согласована, базовая реализация подключена; требуется runtime-проверка в AutoCAD**.

Зафиксированные решения:

1. Настраиваются и входные блоки, и выходные имена блоков карт раскроя.
2. Настройки слоёв и блоков общие для `DETAIL` и `SUMMARY`.
3. Единственный файл настроек: `AutoExtraction\settings.ini` — в корне программы, без проектных override рядом с DWG.
4. В первую версию входят все задачи, включая CUTLINE и CUTSHEET.

---

## 1. Общее правило

Настройки отвечают только за **границу входных данных** и **имя/слои результата**.

Они не меняют:

- алгоритмы агрегации и сортировки;
- правила чтения свойств блоков;
- имена динамических свойств `ДЛИНА`, `ВЫСОТА`, `ШИРИНА`;
- имена атрибутов `ВИТРАЖ` и `МАРКА`;
- геометрию карт раскроя;
- размеры листа/хлыста и ширину реза;
- правила `DETAIL`/`SUMMARY`.

`DETAIL` и `SUMMARY` используют один и тот же набор входных слоёв и блоков. Переключение режима меняет только форму группировки, таблицы и экспорт.

---

## 2. Расположение и жизненный цикл файла

Файл находится рядом с программой:

```text
AutoExtraction\settings.ini
```

Корень определяется там же, где сейчас определяется `extraction.lsp`.

Правила:

- если файла нет, используются встроенные значения по умолчанию;
- при первом сохранении из окна настроек файл создаётся;
- `RELOAD` и каждое открытие `EXTRACTION` перечитывают файл;
- настройки не зависят от папки текущего DWG;
- ручное изменение выбора слоёв в главном окне не перезаписывает INI;
- постоянное изменение выполняется только через кнопку `Настройки`;
- при записи желательно использовать временный файл и резервную копию, чтобы сбой не уничтожил рабочие настройки.

Для совместимости с текущими русскоязычными LSP/DCL-файлами первая версия файла должна записываться в Windows-1251. Окно настроек само сохраняет правильную кодировку.

---

## 3. Задачи, которые должны быть представлены в настройках

| Код | Название | Входные объекты | Выход |
|---|---|---|---|
| `FASONKA` | Фасонка | INSERT | таблица AutoCAD, XLS/CSV, GAL |
| `SUBSYSTEM` | Подсистема | INSERT | таблица AutoCAD, XLS/CSV, GAL |
| `CLADDING` | Облицовка | LWPOLYLINE и INSERT | таблицы AutoCAD, XLS/CSV |
| `VITRAZH` | Витраж | пока модуль-заглушка | пока нет рабочего отчёта |
| `ZAPOLNENIE` | Заполнение | INSERT | таблица AutoCAD, XLS/CSV, GAL |
| `CUTLINE` | Раскрой хлыста | LINE, MLINE, INSERT | карта AutoCAD и выходной блок карты, XLS/CSV |
| `CUTSHEET` | Раскрой листа | LWPOLYLINE, INSERT | карта AutoCAD и выходной блок карты, XLS/CSV |

`DETAIL`/`SUMMARY` относятся к первым пяти задачам. CUTLINE и CUTSHEET имеют собственные диалоги и режим `MAP`, но также используют настройки из общего файла.

---

## 4. Точная семантика входных масок

### 4.1. Маски слоёв

- сравнение без учёта регистра;
- синтаксис масок — правила AutoCAD `wcmatch`;
- `*` — любое количество символов;
- `?` — один символ;
- несколько строк — условие «ИЛИ»;
- маска применяется к фактическому слою объекта;
- одиночная маска `*` означает явно «все слои».

Примеры:

```text
Фасонка*
*Кассет*
Стойк?
*
```

Настройка масок преобразуется в список реально существующих слоёв текущего чертежа. Если ни одна маска не совпала, программа не должна молча переходить к обработке всех слоёв: показывается предупреждение с названием задачи и масками.

### 4.2. Маски имён блоков

Маски блоков также сравниваются без учёта регистра и объединяются по «ИЛИ».

Они применяются только к INSERT. Полилинии и линии от масок имён блоков не зависят.

Поле имени блока должно проверять то имя, которое реально используется конкретной задачей:

- Фасонка: `EffectiveName`;
- Подсистема: `EffectiveName`, при наличии видимости дополнительно доступно отображаемое имя;
- Облицовка: `EffectiveName` и значение видимости;
- Заполнение: `EffectiveName` и значение видимости;
- CUTLINE/CUTSHEET: тип динамического блока, то есть видимость либо `EffectiveName`.

Пустой список масок блоков и одиночная `*` — разные значения:

- `*` — явно разрешить все имена;
- отсутствие ограничения имени — применимо только там, где это разрешено схемой задачи;
- для Облицовки отсутствие масок не должно случайно разрешать все INSERT: штатные маски `*КАССЕТА*` и `*ПАНЕЛЬ*` остаются безопасными значениями по умолчанию.

### 4.3. Неизменяемые защитные исключения

Даже если пользователь указал `*`, из входной выборки всегда исключаются:

- слой `Невидимые`;
- блоки карт прошлых запусков `РАСКРОЙ *` и `РАСКРОЙ ЛИСТА*`.

Эти исключения не выносятся в редактируемые поля окна настроек.

## 5. Значения по умолчанию для входных данных

### Фасонка

```text
Слои:  Фасонка*
       Железо*
Блоки: *
```

Блок дополнительно обязан иметь свойство с именем, содержащим `ДЛИНА`.

### Подсистема

```text
Слои:  Подсистема
       Подсистема алюминиевая
       Подсистема оцинкованная
Блоки: *
```

Имя элемента отчёта берётся из видимости, а если её нет — из `EffectiveName`.

### Облицовка — полилинии

```text
Слои:  *Облицовка*
       *Кассет*
       *Керамогранит*
```

Полилинии фильтруются по слоям; имя блока к ним не применяется.

### Облицовка — блоки

```text
Слои:  *Облицовка*
       *Кассет*
       *Керамогранит*
Блоки: *КАССЕТА*
       *ПАНЕЛЬ*
```

Существующее правило `ПОДРЕЗНАЯ` сохраняется как предметная классификация и не становится маской отбора.

### Витраж

```text
Слои:  Витражи
       Стойк*
       Ригел*
Блоки: *
```

Настройки создаются уже сейчас, но до появления рабочего модуля Витража не дают результата.

### Заполнение

```text
Слои:  Заполнение
       Стекло
       Обозначение ст-т
Блоки: *
```

Атрибуты `ВИТРАЖ` и `МАРКА` остаются отдельными данными блока, а не масками имени.

### CUTLINE

```text
Слои:  *
Блоки: *
```

Настройка ограничивает исходные LINE/MLINE/INSERT до открытия собственного диалога CUTLINE. Внутренний выбор «линии / мультилинии / динамические блоки / все типы» сохраняется.

### CUTSHEET

```text
Слои:  *
Блоки: *
```

Настройка ограничивает исходные LWPOLYLINE/INSERT до открытия собственного диалога CUTSHEET. Выбор типа динамического блока в его диалоге сохраняется.

## 6. Настройка выходных результатов

### 6.1. Обычные отчёты

Фасонка, Подсистема, Облицовка, Витраж и Заполнение не создают выходной блок-обёртку. Они создают таблицы и/или файлы.

Для них в схеме предусматривается:

```text
output.table.layer=CURRENT
```

`CURRENT` сохраняет сегодняшнее поведение. Если пользователь указывает конкретный слой, таблица должна создаваться на нём; отсутствие такого слоя обрабатывается как ошибка настройки, а не как молчаливый переход на другой слой.

У Облицовки это единый слой для таблиц полилиний и блоков.

### 6.2. CUTLINE и CUTSHEET

Для карты раскроя нужны три отдельных параметра:

```text
output.block.template=Раскрой {DWG}
output.insert.layer=CURRENT
output.frame.layer=Невидимые
```

Для CUTSHEET:

```text
output.block.template=Раскрой листа {DWG}
output.insert.layer=CURRENT
output.frame.layer=Невидимые
```

Правила шаблона:

- `{DWG}` заменяется именем текущего DWG без расширения;
- после построения сохраняется действующий механизм уникальности: ` 0`, ` 1`, ...;
- `*` в шаблоне выходного имени не является маской;
- шаблон не должен быть пустым;
- имя не должно начинаться с `*`, чтобы не создавать анонимный блок;
- недопустимые для AutoCAD символы отклоняются при сохранении настроек.

`CURRENT` — это специальное значение, а не имя слоя и не ссылка на файл. Оно означает: оставить текущее поведение AutoCAD и использовать активный слой. В окне настроек это будет показано понятным текстом «Текущий слой».

`output.insert.layer` — слой ссылки на созданный блок. Значение `CURRENT` сохраняет текущий слой.

`output.frame.layer` — слой рамки карты. Внутренние примитивы карты сохраняют свои рабочие слои; настройка не переносит всю карту на один слой.

## 7. Схема INI-файла

Используются нумерованные ключи. Это позволяет хранить имена со spaces и не зависеть от разделителя внутри одной длинной строки.

```ini
; AutoExtraction settings
; Кодировка: Windows-1251

[meta]
version=1

[task.FASONKA]
input.layer.count=2
input.layer.1=Фасонка*
input.layer.2=Железо*
input.block.count=1
input.block.1=*
output.table.layer=CURRENT

[task.SUBSYSTEM]
input.layer.count=3
input.layer.1=Подсистема
input.layer.2=Подсистема алюминиевая
input.layer.3=Подсистема оцинкованная
input.block.count=1
input.block.1=*
output.table.layer=CURRENT

[task.CLADDING]
input.polyline.layer.count=3
input.polyline.layer.1=*Облицовка*
input.polyline.layer.2=*Кассет*
input.polyline.layer.3=*Керамогранит*

input.block.layer.count=3
input.block.layer.1=*Облицовка*
input.block.layer.2=*Кассет*
input.block.layer.3=*Керамогранит*
input.block.name.count=2
input.block.name.1=*КАССЕТА*
input.block.name.2=*ПАНЕЛЬ*
output.table.layer=CURRENT

[task.VITRAZH]
input.layer.count=3
input.layer.1=Витражи
input.layer.2=Стойк*
input.layer.3=Ригел*
input.block.count=1
input.block.1=*
output.table.layer=CURRENT

[task.ZAPOLNENIE]
input.layer.count=3
input.layer.1=Заполнение
input.layer.2=Стекло
input.layer.3=Обозначение ст-т
input.block.count=1
input.block.1=*
output.table.layer=CURRENT

[task.CUTLINE]
input.layer.count=1
input.layer.1=*
input.block.count=1
input.block.1=*
output.block.template=Раскрой {DWG}
output.insert.layer=CURRENT
output.frame.layer=Невидимые

[task.CUTSHEET]
input.layer.count=1
input.layer.1=*
input.block.count=1
input.block.1=*
output.block.template=Раскрой листа {DWG}
output.insert.layer=CURRENT
output.frame.layer=Невидимые
```

Секции не разделяются на `DETAIL` и `SUMMARY`: обе разновидности отчёта читают одну секцию задачи.

## 8. Интерфейс окна настроек

### 8.1. Главное окно EXTRACTION

В верхней строке:

```text
Настройка задачи                         [Настройки] [?]
```

`Настройки` закрывает главное модальное окно, открывает окно настроек, а после сохранения или отмены возвращает пользователя в EXTRACTION. Это надёжнее, чем открывать второй DCL поверх активного `start_dialog`.

### 8.2. Окно «Настройки EXTRACTION»

Верхняя часть:

```text
Задача: [Фасонка                         v]
```

В список задач входят:

- Фасонка;
- Подсистема;
- Облицовка;
- Витраж;
- Заполнение;
- Раскрой хлыста;
- Раскрой листа.

Радиокнопок `DETAIL/SUMMARY` в этом окне нет: настройки общие для обоих режимов.

Для Фасонки, Подсистемы, Витража и Заполнения:

```text
Входные слои
[список масок слоёв                         ]
[Добавить] [Изменить] [Удалить]

Входные блоки
[список масок имён блоков                   ]
[Добавить] [Изменить] [Удалить]

Выходная таблица
Слой: [CURRENT                            ]
```

Для Облицовки показываются две независимые секции:

```text
Полилинии
Слои: [маски слоёв]

Динамические блоки
Слои: [маски слоёв]
Имена: [маски блоков]

Выходные таблицы
Слой: [CURRENT]
```

Для CUTLINE и CUTSHEET:

```text
Входные слои
[список масок слоёв]

Входные динамические блоки
[список масок имён блоков]

Результат карты
Шаблон имени блока: [Раскрой {DWG}       ]
Слой вставки блока: [CURRENT            ]
Слой рамки:         [Невидимые            ]
```

Под списками выводится подсказка:

```text
* — любое количество символов; ? — один символ.
Маски объединяются по ИЛИ. Одиночная * означает «все».
```

Нижняя строка кнопок:

```text
[По умолчанию]       [Сохранить] [Отмена]
```

`По умолчанию` сбрасывает только выбранную задачу и требует подтверждения. `Сохранить` проверяет значения, записывает `AutoExtraction\settings.ini` и применяет их. `Отмена` закрывает окно без изменения файла.

### 8.3. Что не показывать в окне

Не показывать пользователю:

- служебные исключения карт раскроя;
- имена свойств `ДЛИНА`/`ВЫСОТА`/`ШИРИНА`;
- имена атрибутов;
- алгоритмические лимиты и параметры солвера;
- внутренние имена функций.

## 9. Поведение при запуске

1. `EXTRACTION` находит `AutoExtraction\settings.ini`.
2. Читает секции и проверяет версию.
3. Для текущей задачи разворачивает маски в конкретные слои текущего DWG.
4. Показывает их в обычном списке слоёв.
5. Пользователь может временно изменить выделение слоёв для текущего запуска.
6. Нажатие `Сохранить` не меняет INI, если пользователь не заходил в `Настройки` и явно не нажал там `Сохранить`.
7. После запуска задачи действуют выбранные слои и маски текущей задачи.
8. `DETAIL` и `SUMMARY` используют те же входные ограничения.
9. CUTLINE/CUTSHEET дополнительно применяют свои штатные диалоги типов объектов.

Если в секции нет ключа или значение повреждено:

- применяется значение по умолчанию для конкретного ключа;
- в командной строке выводится предупреждение с секцией и ключом;
- EXTRACTION не падает целиком из-за одной плохой строки.

---

## 10. Порядок проверки и последующей реализации

Базовые пункты 1–7 уже реализованы в LSP/DCL. Не выполнена только runtime-проверка в AutoCAD и проверка фактической записи `settings.ini`.

Порядок проверки и остаточных работ:

1. проверить в AutoCAD DCL, модальность и кодировку CP1251;
2. сохранить настройки для каждой задачи и проверить создание `AutoExtraction\settings.ini`;
3. провести регресс по всем задачам, обоим режимам, RELOAD и перезапуску AutoCAD;
4. при необходимости усилить runtime-регрессию для недопустимых символов шаблона имени блока.
