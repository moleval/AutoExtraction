# ТЗ для репозитория `moleval/MarkZ`: проверки кода — зона AutoExtraction

**Адресат:** ветка разработки MarkZ (актуальная редакция — `Ред. 48.38+`, файл `MARKZ.lsp`).
**Источник задания:** репозиторий `moleval/AutoExtraction`, ветка `arena/188fd430-autoextraction`,
коммит `25d914c`.
**Документ-основание:** `tests/CHKPARENS.md`, `HANDOFF_TZ.md` (запись «CHKALL: тихий режим
и автозапуск только при сбое»).

---

## 0. Принцип

**Проверками владеет AutoExtraction, а не MarkZ.**

AutoExtraction — это загрузчик (`reload.lsp`), он знает состав проекта, пути из реестра
`[plugins]` и порядок загрузки. MarkZ загружается **только** через него. Поэтому решение
«когда и что проверять» принимает загрузчик, а модуль не дублирует эту логику.

Следствие: MarkZ не запускает проверки кода вообще — ни своих, ни чужих. Проверки данных
чертежа (TEST 01–16) остаются: это не проверки кода.

---

## 1. Что убрать

### 1.1. Вызов при загрузке (главное)

Хвост `MARKZ.lsp`, перед баннером загрузки:

```lisp
(mark:test-parens)                                   ; <-- удалить эту строку
(mark:emit (strcat "\n[MARKZ] " ... " загружена."))
```

**Это единственное место, из-за которого проверки идут на каждом `RELOAD`.**
`mark:test-parens` при наличии команды `CHKALL` вызывает `c:CHKALL` — то есть полный обход
всех модулей проекта и всех плагинов, 27 файлов по две строки в лог, на каждую перезагрузку.

### 1.2. Строка в списке диагностики

`mark:diagnostics`:

```lisp
(defun mark:diagnostics ()
  (mark:safe 'mark:test-parens             "TEST 00")   ; <-- удалить
  (mark:safe 'mark:test-fillings           "TEST 01")
  ...
```

### 1.3. Функции, которые после этого не нужны

| Функция | Судьба |
|---|---|
| `mark:test-parens` | удалить |
| `mark:scan-parens` | удалить |
| `mark:has-command?` | удалить (использовалась только для поиска `c:CHKALL` в `atoms-family`) |

### 1.4. Тексты и документация

- шапка `MARKZ.lsp`: «Режим самодиагностики TEST 00 … TEST 14» → «TEST 01 … TEST 16»;
- `AGENTS.md`, п. 2: фраза «Модульные проверки — только страховка на случай, когда
  AutoExtraction не загружен: `TEST 00` (MarkZ, печатается при загрузке)» — заменить на:
  «Проверка кода — только через AutoExtraction: `CHKALL` (краткий отчёт), `CHKALLFULL`
  (подробный), `CHKFILE` (один файл), `CHKLOAD` (место сбоя). Своего сканера в модуле нет»;
- `README.md` и `TZ.md`: убрать `TEST 00` из перечней самодиагностики.

### 1.5. Что НЕ трогать

`mark:find-source`, `*mark:source-candidates*`, `mark:file-open?` — **остаются**.
Их использует `mark:snapshot-path` (снимок геометрии кладётся рядом с исходником), к
проверкам они отношения не имеют.

---

## 2. Что оставить и почему

`TEST 01`–`TEST 16` — проверки **данных чертежа**, а не кода: блоки заполнений, атрибуты
витража, динамические свойства, видимость, атрибут «Марка», уникальные размеры, нумерация,
спецсостояния, секции и ярусы, соответствие «номер марки = номер ригеля». Доктор
AutoExtraction их не заменяет: он читает только текст `.lsp` и в чертёж не смотрит.

Остаются без изменений: `mark:diagnostics` (без строки TEST 00), `mark:safe`, `mark:note-error`,
`mark:note-warning`, счётчик `*mark:errors*`.

---

## 3. Почему доктора AutoExtraction достаточно

| Возможность | AutoExtraction | Сканер MarkZ (TEST 00) |
|---|---|---|
| Баланс скобок | `CHKALL`, `CHKFILE` | да |
| Незакрытая кавычка | да | да |
| BOM в начале файла | да | **нет** |
| Управляющие байты, не-ANSI вне строк | да | **нет** |
| Скрытые байты (сверка размера с содержимым) | да | **нет** |
| Локализация сломанной формы (бисекция) | `CHKLOAD` | **нет** |
| Проверка **того самого** файла, что загружается | да — путь из реестра `[plugins]` тем же резолвером `ae-reload-plugin-resolve`, что у `RELOAD` | **нет** — `mark:find-source` идёт по путям поддержки и кандидатам (`D:/MARKZ.lsp`, `D:\MARKZ.lsp`), может найти старую копию |
| Разбор форм: `if` ≤ 3, `defun` ≥ 3, `foreach/while/repeat` 2–3 | `tests/static_check.py` (`special-forms`) | **нет** |
| Дубли `defun` в файле и между модулями | `defun-dup-in-file`, общий поиск | **нет** |
| Арность вызовов | `call-arity` | **нет** |
| Автозапуск | `RELOAD`: при `errors > 0` — тихий `CHKALL` по всем файлам | был автозапуск на каждой загрузке |

Два отдельных аргумента:

1. **Проверка на загрузке физически не может сработать.** Если в `MARKZ.lsp` нарушен
   синтаксис, AutoCAD не загрузит файл — `(mark:test-parens)` просто не выполнится.
   Единственный реальный сценарий, который ловил TEST 00, — «проверялся не тот файл»
   (старая копия в путях поддержки). Именно этот сценарий и убирается вместе с TEST 00.
2. **`MARKZ.lsp` уже в реестре плагинов** (`settings.ini`, `[plugins]`, `D:\MarkZ\MARKZ.lsp`).
   `CHKALL` берёт путь из реестра, поэтому проверяется ровно загружаемый файл. Отдельная
   проверка внутри модуля дублирует это и слабее по составу.

## 4. Необязательный вариант (если удалять не хочется)

Оставить «проверку исходника» как **тонкую обёртку** без своего сканера и без `c:CHKALL`:

```lisp
;; Не рекомендуется: дублирует CHKALL. Если оставлять — только так.
(defun mark:test-parens (/ src)
  (if (member (type chk-parens-scan) '(SUBR USUBR))
    (progn
      (setq src (mark:find-source))
      (if src (chk-parens-scan src nil)))))
```

и вызывать его **не при загрузке**, а только из `mark:diagnostics`. Условие: никаких
`atoms-family`, никакого `c:CHKALL`, никакого собственного сканера.

Предпочтительный вариант — полное удаление (раздел 1).

## 5. Приёмка

1. `RELOAD` в AutoCAD:
   - в логе **нет** строк `[TEST 00] Прогон скобок — CHKALL (AutoExtraction)` и
     `[TEST 00] Отчёт CHKALL — выше в логе.`;
   - идут только `[MARKZ] Ред. … загружена.` и таблица команд;
   - нет простыни `[CHK] <файл> размер N байт` / `ИТОГ: 0 (OK)`.
2. `CHKALL` — краткий отчёт: только проблемные файлы и `[CHK] всего проблем: N`.
   `CHKALLFULL` — подробный, `D:\MarkZ\MARKZ.lsp` присутствует в обходе.
3. Сломанный `MARKZ.lsp` (снять одну `)`): `RELOAD` печатает `ОШИБКА ЗАГРУЗКИ`,
   затем `--- диагностика файла: скобки, строки, скрытые байты ---`,
   `--- поиск формы со сбоем (CHKLOAD) ---` и в конце
   `--- CHKALL: проверка всех файлов после сбоя загрузки ---`. Строка файла и место сбоя
   названы.
4. `МАРКАЗ` на рабочем чертеже: `TEST 01`…`TEST 16` печатаются как раньше, марки строятся.
5. `*mark:errors*` не поднимается из-за отсутствия TEST 00; блокировка построения марок
   по синтаксису (`mark:note-error` в TEST 00) исчезает вместе с TEST 00.

---

## 6. Риски и ограничения

- Если MarkZ загрузить **без** AutoExtraction (`APPLOAD`), проверок кода не будет вообще.
  Это принято: штатная загрузка — только через `RELOAD`. В `README.md` стоит указать это
  одной строкой.
- `МАРКАВСКОБКИ` в `MarkV.lsp` — та же история (вызывает `CHKALL`, иначе встроенный сканер).
  Правится отдельным этапом по этому же принципу; в текущее задание не входит.
- Поведение рабочих команд не меняется: удаляются только проверки и их вызовы.
