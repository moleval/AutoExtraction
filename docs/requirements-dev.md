# Требования к разработке и окружению

## 1. Языки и инструменты
- **AutoLISP / Visual LISP** — основной язык разработки.
- **DCL** — для диалоговых окон.
- **Visual Studio Code** — рекомендуемый редактор (расширение AutoCAD AutoLISP).
- **Git** и **GitHub** — контроль версий.
- **Python 3** — для вспомогательных скриптов (экспорт кода).

## 2. Кодировка
- Все файлы `.lsp` и `.dcl` должны быть в кодировке **Windows-1251 (ANSI)**.
- Markdown-файлы (`.md`) — в **UTF-8** (без BOM). Все `.md` в репозитории уже приведены к UTF-8.
- В VS Code задать `"files.encoding": "windows1251"` для LISP-файлов.

## 3. Структура проекта
- Исходный код разделён на каталоги:
  - `common/` — общие библиотеки.
  - `Extraction/` — модули задач и диспетчер.
  - `Plugins/` — принятые сторонние плагины, поставляемые с проектом (папка создаётся при необходимости; в репозитории её пока нет).
  - `tests/` — тесты (Python без AutoCAD и LSP-тесты для AutoCAD), см. [tests/README.md](../tests/README.md).
  - `scripts/` — служебные скрипты (`scripts/test.ps1` — запуск тестов).
  - `docs/` — документация.
- Именование функций с префиксами:
  - `tu-` — утилиты общего назначения;
  - `dsp-` — функции диспетчера;
  - `fasonka-` — функции задачи «Фасонка».

## 4. Модульность
- Задачи не должны содержать дублирующийся код; общие операции выносятся в `common/`.
- `extraction.lsp` только собирает параметры и вызывает `run-task`.
- Каждая задача реализуется функцией `*-main` с одинаковой сигнатурой:
  `(task-main layers report-mode export-excel export-txt create-table save-base)`.

## 5. Тестирование
- Перед коммитом запускать `scripts\test.ps1` (или по отдельности `python tests\static_check.py` и логические тесты `tests\*_test.py`).
- Изменения в `.lsp` проверяются в AutoCAD: `CHKALL` (баланс скобок и кодировка), затем `RELOAD`.
- Ручное тестирование в AutoCAD 2016 и 2023.
- Проверка кириллицы при загрузке.
- Проверка больших наборов данных (1000+ блоков) на скорость и корректность.
- Живые прогоны фиксируются в журнале [HANDOFF_TZ.md](../HANDOFF_TZ.md) или в протоколе приёмки (например, [acceptance-v3-v5-v6.md](acceptance-v3-v5-v6.md)).

## 6. Git
- Основная ветка: `main`.
- Для новых задач создавать ветки `feature/<имя>`.
- Коммиты должны быть атомарными с осмысленными сообщениями на русском или английском.

## 7. Документация
- Каждое изменение функциональности должно отражаться в `docs/requirements.md` и `docs/promt.md`.
- Структура проекта поддерживается в `docs/structure.md`.
