# Как запускать тесты AutoExtraction

## Требования

- Python **3.8** или новее (проверьте: `python3 --version` или `py --version`).
- Ничего больше ставить не нужно — используются только стандартные библиотеки.

## Запуск

Из корня репозитория:

```bash
# Linux / macOS
python3 tests/run_stage5_tests.py

# Windows
py tests\run_stage5_tests.py
```

С подробным стеком ошибок:

```bash
python3 tests/run_stage5_tests.py --verbose
```

## Что печатает прогон

Каждая строка — один тест:

```
[OK ] 1.3 Регрессия счётчика (2 одинаковых блока) — PASS
[!!!] 4.5 Полный путь: диалог → Заполнение → запуск — FAIL
     <сообщение об ошибке>
```

В конце сводка:

```
ИТОГ: 24/24 PASS, 0 FAIL/ERROR
```

- `[OK ] ... PASS` — проверки теста выполнены;
- `[!!!] ... FAIL` — проверка не выполнена (assert): результат отличается от ожидаемого;
- `[!!!] ... ERROR` — тест упал с исключением (обычно ошибка самого кода или харнесса).

## Коды выхода

- `0` — все тесты прошли;
- `1` — есть FAIL/ERROR.

## Что проверяется (группы)

- **Группа 6** (выполняется первой): регрессия — «Фасонка» и «Подсистема»
  через диспетчер `run-task` не сломаны.
- **Группа 1**: одиночные блоки «Заполнения», граничные случаи + регрессии
  трёх исправленных дефектов (см. `РАЗБОР-ДЕФЕКТОВ.md`).
- **Группы 2/3**: несколько блоков, несколько слоёв, агрегация, предвыбор.
- **Группа 4**: диспетчер EXTRACTION — отмена, несуществующая задача,
  отсутствующие модули, полный путь «Заполнения», кнопки «Раскрой хлыста»
  и «Раскрой листа» (регрессия дефекта `CUTLINE-MAIN`).
- **Группа 5**: экспорт XLS (подробный/краткий), GAL, путь по умолчанию,
  занятый файл, интерактивная команда `ZAPOLNENIE`.

## Если тест упал

1. Запустите с `--verbose` и посмотрите стек (`Traceback`).
2. Файлы и сообщения об ошибках системы пишутся в тестовую консоль —
   хвост консоли выводится в сообщении FAIL.
3. Временные файлы каждого теста лежат в `tests/tmp_stage5/<номер>/`
   (экспортированные XLS/GAL и т.п.).

## Как устроены моки (для изменения тестов)

- «Чертёж» строится кодом: `ctx.add_layer(...)`, `add_zap_block(...)`,
  `add_len_block(...)` — создают INSERT-примитивы с динамическими
  свойствами (имя видимости, «Высота в свету», «Ширина в свету», «ДЛИНА»).
- Ввод пользователя скриптуется: `ctx.set_inputs(("string", ...),
  ("kword", ...), ("enter", None), ("point", [x,y,z]))`.
- Диалоги DCL — `ctx.dialog_script(("click", "btn_save"),
  ("set", "rb_detail", "1"))`.
- Предвыбор — `*EXTRACTION-PRESELECTED-SET*` через `interp.assign(...)`
  (см. тест 3.3) или `ctx.set_pickfirst([...])`.
- «Занятый» файл — `ctx.lock_file("имя.csv")` / `ctx.unlock_file("имя.csv")`:
  `open` вернёт `nil`, как в AutoCAD.

## Добавление нового теста

1. Откройте `tests/run_stage5_tests.py`.
2. Напишите функцию `def tX_Y(rec):` по образу соседних.
3. Зарегистрируйте её в `main()` вызовом `run_case("X.Y Название", tX_Y)`.
4. Проверяемые строки консоли берите из самих `.lsp` (команда
   `grep`/`iconv`), не из догадок.

## Ограничения

- Это НЕ заменяет проверку в реальном AutoCAD: геометрия примитивов,
  AutoCAD-таблицы и диалоги отрисовываются моками упрощённо.
- Симуляция таблиц AutoCAD (zapolnenie-create-table-*) в харнассе не
  реализована — тест диспетчера выключает её через
  `*EXTRACTION-LAST-CREATE-TABLE*`.

⚠️ Все исходники проекта — в кодировке **CP1251**. Файлы тестов — UTF-8.
Не пересохраняйте `.lsp`-файлы в UTF-8: русские строки развалятся.
