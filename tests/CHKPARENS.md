# CHKPARENS — проверка баланса скобок LSP-файлов

Назначение: находить «лишнюю» или «непропущенную» скобку в `.lsp`-файлах
до/вместо анализа ошибки загрузки. Читает файл построчно, считает
баланс: `(` ? +1, `)` ? ?1.

## Что игнорируется
- строковые литералы в кавычках `"..."`, включая экранированные `\"`;
- комментарии от `;` до конца строки.

## Команды
| Команда | Действие |
|---|---|
| `CHKALL` | проверить все `*.lsp` в `common\`, `Extraction\` и корне проекта |
| `CHKFILE` | проверить один файл (путь вводится вручную) |

Загрузка проверки: `(load "D:/AutoExtraction/tests/chkparens.lsp")`
(или `APPLOAD`). Также подгружается автоматически из `reload.lsp`,
если файл существует.

## Чтение вывода
- `[CHK] <путь> ИТОГ: 0 (OK)` — файл цел.
- `[CHK] <путь> ИТОГ: n (не закрыто)` — не хватает n закрывающих скобок.
- `[CHK] <путь> БАЛАНС n ПЕРЕД строкой N: (defun …` — предыдущая функция
  верхнего уровня не закрыта (искать скобку в ней).
- `[CHK] <путь> ЛИШНЯЯ ЗАКРЫВАЮЩАЯ строка N` — лишняя `)` в строке N.
- `[CHK] всего проблем: 0` — все файлы чисты.

Примечание: сообщения печатаются только для `defun` верхнего уровня
(строка начинается с `(` в нулевой колонке), поэтому вложенные
`(defun *error* …)` ложных срабатываний не дают.

## Типовой цикл после правки
1. `CHKALL` — найти битый файл и строку.
2. Исправить в редакторе.
3. `CHKALL` — убедиться `ИТОГ: 0`.
4. `RELOAD` — штатная перезагрузка модулей.

## Интеграция с RELOAD
- Успешные старты: сканирование НЕ выполняется (ноль накладных расходов).
- Ошибка загрузки: `reload.lsp` автоматически вызывает
  `chk-parens-scan` для упавшего файла и печатает строку с небалансом.
- Guard: `(= (type chk-parens-scan) 'SUBR)` — если проверка не загружена,
  `RELOAD` работает как раньше.

## Ограничения
- путь в `CHKFILE` вводится вручную; `CHKALL` опирается на `extraction.lsp`
  для определения корня проекта;
- не проверяет парность кавычек и квадратные скобки;
- не понимает многострочные строковые литералы.

## Лексические проверки (2026-10-07)

Баланс скобок может быть нулевым, а загрузка всё равно падает с
`синтаксическая ошибка` — AutoCAD читает `.lsp` как ANSI. Сканер дополнительно
сообщает:

- `BOM (байт 239)` в начале файла — пересохранить без BOM;
- `управляющий символ (код N)` — посторонний байт < 32;
- `строковая константа не закрыта` — нет закрывающей кавычки в строке;
- `не-ANSI символ вне строки/комментария (слово "…")` — символ > 127 в коде
  (имена команд вида `c:ИМЯ` считаются допустимыми);
- `есть скрытые байты (NUL или смешанные переводы строк)` — размер файла
  не сходится с числом прочитанных символов;
- `размер N байт` — печатается всегда: по нему сверяется, та ли версия файла
  лежит на диске (например, `cutsheet.lsp` ред. 25 — 88 278 байт).

Тот же набор проверок есть в `tests/static_check.py` (группа `lexical`) —
по всем `*.lsp` проекта.

## CHKLOAD — поиск места сбоя загрузки

Когда баланс скобок цел, а `(load)` всё равно падает с «синтаксической ошибкой»
(например, файл на диске отличается от версии в репозитории), нужен точный
виновник. `CHKLOAD` режет файл на префиксы по границам верхнеуровневых форм
(строка начинается с `(`, баланс до неё — 0), пишет префикс во временный файл
и грузит его. Первый падающий префикс указывает форму со сбоем:

```
[CHKLOAD] D:\...\cutsheet.lsp, строк 1919, форм верхнего уровня 145
[CHKLOAD] СБОЙ В ФОРМЕ, строки 735..956
[CHKLOAD]   735: ;; ============...
[CHKLOAD]   736: (if (not (boundp '*cs-created*))
[CHKLOAD]   737:   (setq *cs-created* nil)
```

Если все префиксы грузятся, а файл целиком — нет, в отчёте будет
`префиксы грузятся, а файл целиком — нет`: значит содержимое разбирается,
и причина в чём-то ещё (например, в переводе строк на диске).

Вызов: автоматически из `reload.lsp` при ошибке загрузки модуля; вручную —
команда `CHKLOAD` (путь вводится). Временные файлы удаляются.

### Формула «скрытых байт»

Размер файла сверяется с числом прочитанных символов по окну допустимых
значений: от `символы + строки - 1` (LF, последняя строка без перевода) до
`символы + 2*строки` (CRLF, перевод после последней строки). Внутри окна
срабатываний нет: файл, сохранённый с `CRLF`, проблемой не считается —
раньше он давал ложное «есть скрытые байты».

### Что печатает CHKLOAD

```
[CHKLOAD] <файл>, строк N, символов S, форм верхнего уровня K
[CHKLOAD] грузятся префиксы — сообщения модуля ниже к загрузке не относятся
[CHKLOAD] загрузка всего файла: синтаксическая ошибка
[CHKLOAD] СБОЙ В ФОРМЕ №K, строки A..B | ошибка: синтаксическая ошибка
[CHKLOAD]   A: (defun ...
```

Если все префиксы грузятся, а целый файл — нет, печатается
`копия файла (LF) грузится, а сам файл — нет (дело не в содержимом форм)`:
значит содержимое разбирается читателем, и причину надо искать вне форм.
