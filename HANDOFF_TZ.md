## 7. Жёсткие правила и ограничения

**Из раздела «Чего НЕ делаем» (зафиксировано):**
- Не переписываем `fasonka`, солверы (FFD/MaxRects), не объединяем `*-main` в «универсальную» функцию.
- Не делаем бог-объект `utils.lsp`; механически не заменяем `append`/`foreach`.
- Не вводим десятки `*flag*`; не оборачиваем КАЖДУЮ строку в `vl-catch-all`.
- HARD-лимиты — только именованные переменные с дефолтами; SOFT-пороги не «чинят» значение автоматически (никаких «0.35 → 35»).
- **Алгоритмику раскроя не трогаем.** Перф-правки должны быть поведение-сохраняющими: тот же состав и порядок примитивов, те же координаты, те же XLS.

**Рабочие конвенции (выстраданы на практике):**
- **Кодировка всех `.lsp` — cp1251 (ANSI)**, AutoCAD читает ANSI. Патч-скрипты читают/пишут строго `cp1251`. Markdown-файлы репозитория — UTF-8.
- **Grep по кириллице** только через `iconv -f cp1251 -t utf-8 файл | grep …`, иначе 0 совпадений молча.
- **Проверка баланса скобок** после каждой правки — полным сканером с учётом строк, комментариев `;` и экранирования `\"` (в репо есть `tests/chkparens.lsp` и `tests/static_check.py` — прогонять после каждой правки).
- **Патч-скрипты идемпотентны**: проверка «уже пропатчено» + `assert count(old)==1` перед заменой. Скрипты держать в `/tmp`, новый на задачу.
- Один дефект/рефакторинг → один коммит с понятным сообщением.
- Единый формат ошибок: `[AutoExtraction][MODULE][KIND] текст` (KIND: `VALIDATION`, `ACTIVE-X`, `IO`, `GUARD`).
- **У пользовательской функции AutoLISP нет необязательных аргументов.** Вызов с меньшим числом аргументов, чем параметров в `defun`, — ошибка «слишком мало аргументов», и она рвёт команду целиком. Добавляя параметр, править **все** вызовы и передавать `nil` явно; лишние аргументы так же недопустимы. Держит группа `call-arity` в `tests/static_check.py`.

## 13. Фильтры слоёв — групповая фильтрация (2026-10-07)

**Задача (ТЗ пользователя):** переработать фильтры слоёв диспетчера на работу по именам ГРУППОВЫХ фильтров AutoCAD с поддержкой вложенности.

```text
Все (уровень 0)
`- Стройплэкс (1)
   |- Витражи (2)
   |- Окна (2)
   |- Отключенные (2)      <- входит в «Мои» ЯВНО (точным именем), даже если окажется вне «Стройплэкс»
   |- Фасад - Облицовка (2)
   |- Фасад - Подсистема (2)
   `- Фасад - Утепление (2)
```

**Окно (Extraction/extraction.dcl):** четыре чекбокса `Мои | Фасады | Витражи | Окна` (ключи `chk_filter_my / chk_filter_facades / chk_filter_vitrazh / chk_filter_windows`); `chk_filter_anonymous` (Анонимные блоки) — отдельно, в систему фильтров слоёв не входит. Старые чекбоксы `Фасады / Витражи / Фонарь 3D` и переменные `*EXTRACTION-FILTER-FACADES/VITRAZH/FONAR*` удалены полностью.

**Состав встроенных фильтров (`common/layer-utils.lsp`, ред. 2):**
- `Мои` = рекурсивно весь `Стройплэкс` (прямые слои + все вложенные группы любого уровня) + `Отключенные` по точному имени + фильтры по маскам `Фасад*`, `Витраж*`, `Фонар*`, `Окн*`;
- `Фасады` = маска `Фасад*`; `Витражи` = `Витраж*`, `Фонар*`; `Окна` = `Окн*`; тематические маски ищутся на уровнях 1–2, берутся ПРЯМЫЕ слои найденных групп;
- маски/имена/уровни — именованные переменные `*tu-layer-filter-*` (меняются без правок кода); несколько чекбоксов объединяются по «или» без дублей; сравнение без учёта регистра и пробелов по краям; маска с `*` — шаблон wcmatch, без `*` — точное имя;
- защита от циклов (список посещённых объектов/имён), отсутствие словаря групповых фильтров — не ошибка.

**Состояние диспетчера:** `*EXTRACTION-LAYER-FILTERS*` (текущее), `*EXTRACTION-LAST-LAYER-FILTERS*` (между открытиями окна), `*EXTRACTION-LAYERS-SOURCE*` ('FILTER / 'MANUAL / nil). Единый обработчик `extraction-layer-filter-changed` для всех четырёх чекбоксов: читает состояние → запоминает → перестраивает `lst_layers` → сохраняет только тот ручной выбор, который остался видимым. Приоритет слоёв для задачи: ручной выбор → слои фильтра → все слои (nil). Фильтр активен, но слоёв нет — задача НЕ запускается (alert + `[EXTRACTION][LAYER-UTILS]`), молчаливая подмена всеми слоями запрещена. Диагностика также выводится в строку-подсказку окна (`txt_layers_hint`).

**Различение причин пустого фильтра (после первого прогона пользователя):** `available-p` считается по дереву, а не по наличию словаря (расширенный словарь слоёв есть почти всегда, из-за чего «фильтров нет» выглядело как «совпадений нет»). В окне — короткий текст без служебных меток: «Групповой фильтр отсутствует» / «Нет слоев по фильтру: Мои» (плитка обрезает длинные строки), в командной строке — сообщение с меткой `[EXTRACTION][LAYER-UTILS]` (тексты дают `extraction-layer-filter-problem-text` / `-hint-msg` / `-fail-msg`).

**CUTLINE (ред. 14-17) / CUTSHEET (ред. 24-25):** слои — через общий `extraction-resolve-layers` (ручной выбор приоритетен; слои фильтра чистятся от `0`/`DEFPOINTS`); подпись источника — `по фильтру: Мои` / `по фильтрам: Фасады, Окна`; модули больше не читают переменные фильтров напрямую.

**Приёмка — `tests/layer-filter-test.lsp` (команда `LAYERFILTERTEST`):** печатает дерево фильтров (имя, уровень, родитель, прямых слоёв) и выполняет автопроверки: состав «Мои», явное включение «Отключенные», отсутствие дублей, разделение тематических фильтров, критическое условие «слой, входящий только в Отключенные, виден в Мои и скрыт в Фасады/Витражи/Окна», пустой список фильтров = «все слои».
